# مختبر أعطال HTTP

أداة هندسية داخلية تختبر سيناريوهات سنستخدمها للتحقق من محرك التنزيل. ليست تطبيق التنزيل ولا خدمة منتج. تعمل دون تبعيات npm خارجية ولا تصل إلى الإنترنت أو ملفات المستخدم.

## التشغيل

يتطلب Node.js 22 أو أحدث. من جذر المشروع:

```sh
npm test
npm run lab:serve
```

على PowerShell يمكن استخدام `npm.cmd` إذا حجبت سياسة الجهاز `npm.ps1`. الخادم يستمع على `127.0.0.1` ومنفذ عشوائي يطبعه عند البدء. يمكن تحديد المنفذ بمتغير `FHD_LAB_PORT`. أوقفه بـCtrl+C. لا يُشغّل تلقائيًا عند تسجيل الدخول.

## السيناريوهات

| المسار | السلوك |
| --- | --- |
| `/file` | 64 KiB ثابتة، ETag قوي، GET وHEAD وRange مفرد وIf-Range |
| `/no-range` | يتجاهل Range ويرجع كامل الملف |
| `/drop` | يقطع الاتصال بعد جزء من البيانات |
| `/drop-once` | يقطع أول GET كامل بعد 32 KiB ثم يسمح بالاستكمال بنفس ETag |
| `/changed-once` | يقطع أول GET كامل ثم يقدم إصدارًا مختلفًا بالحجم نفسه؛ If-Range القديم يرجع 200 |
| `/wrong-range-once` | يقطع أول GET كامل ثم يرجع إزاحة Content-Range خاطئة في طلب الاستكمال |
| `/no-range-once` | يقطع أول GET كامل ثم يتجاهل Range ويرجع الملف كاملًا |
| `/short-body` | ينهي استجابة أقصر من Content-Length المعلن |
| `/wrong-range` | يعطي Content-Range خاطئًا عمدًا عند طلب نطاق |
| `/slow` | دفعات صغيرة متأخرة |
| `/redirect` | تحويل نسبي إلى الملف |
| `/loop` | تحويل دائري لاختبار حدود التتبع |
| `/status/{code}` | 403 و404 و429 و500 و502 و503؛ Retry-After لبعض الأخطاء المؤقتة |

للتغيير بين نسختين بنفس الحجم، يستدعي الاختبار `lab.changeVersion()` عبر واجهة البرمجة المحلية؛ لا توجد نقطة HTTP لتغيير الحالة. كل مختبر اختبار معزول بمنفذ مستقل، ويلتقط الطلب نسخة ثابتة من المورد.

مسارات `-once` مستقلة عن `/file` وعن بعضها. HEAD وطلب Range لا يستهلكان حدث القطع الأول؛ تتجدد حالتها عند إنشاء مثيل مختبر جديد. الحجم ثابت 65,536 بايت لتجاوز عتبة checkpoint في اختبار المحرك دون ملفات كبيرة.

## تكامل محرك Rust

تُبنى أداة المحرك أولًا ثم يشغل الاختبار عملياتها كعميل حقيقي أمام مختبر loopback، ويكتب ملفات داخل مجلد مؤقت خاص بكل اختبار وينظفه بعد إغلاق العمليات:

```powershell
./tools/rust.ps1 -CargoArguments @('build', '-p', 'download-engine', '--bin', 'fhd-transfer', '--locked', '--offline')
node tools/http-lab/engine.test.mjs
```

المسار الافتراضي للأداة `target/debug/fhd-transfer.exe` على Windows و`target/debug/fhd-transfer` على الأنظمة الأخرى. يمكن ضبط `FHD_TRANSFER_BIN` لاختيار مسار أداة مبنية مسبقًا. لا يتجاوز الاختبار غياب الأداة بالتخطي؛ يجب بناؤها أولًا. يرسل عنوان المورد إلى stdin للأداة ويغلقه، ويستعمل مهلة 15 ثانية لكل عملية.

نتيجة فعلية في 2026-09-21 على Windows x64: **21/21 اختبار خادم** و**13/13 اختبار تكامل**. التكامل يثبت تنزيل الملف ومطابقة بصمته، التحويل، استكمال الانقطاع، رفض تغير المورد والنطاق الخاطئ وتجاهل Range دون إلحاق، عدم استبدال ملف مستخدم، الاستعادة بعد قتل عملية عند checkpoint، رفض بصمة غير صحيحة، التنزيل الأولي دون Range، حصة الحجم قبل إنشاء المهمة، وربط اسم المخرج أثناء الاستكمال وبعد الإكمال.

المحاولة الأولى للتكامل منعت البيئة المقيدة إنشاء العمليات الفرعية بـ`spawn EPERM`. نجحت إعادة تشغيل الأمر نفسه بصلاحية تنفيذ موسعة بعد قبول الأداة؛ لم تُحذف اختبارات أو تُغيّر شروط النجاح. اختبار الخادم وحده لا يحتاج عملية فرعية. نجاح الاختبارات لا يثبت صلاحية macOS أو Linux.

## حدود الدليل

اختبارات `server.test.mjs` تتحقق من الخادم وإعادة تركيب النطاقات في الذاكرة. اختبارات `engine.test.mjs` تتحقق أيضًا من محرك Rust وملفاته وعمليات استعادة محددة؛ قتل العملية ليس محاكاة انقطاع كهرباء أو فساد وسيط تخزين. لا يدعم المختبر بعد TLS أو HTTP/2 أو HTTP/3 أو ملفات ضخمة أو محاكاة عطب القرص. يرفض النطاقات المتعددة والمشوهة بـ416 كسياسة اختبار مبسطة، ولا يدعي تنفيذ كل دلالات HTTP.

يرفض Origin وHost غير المتوقع ولا يوفر CORS؛ مخصص لعملاء الاختبار المحليين. لا يُعرض على الشبكة العامة.
