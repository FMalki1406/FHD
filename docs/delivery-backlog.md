# قائمة تنفيذ الإطلاق المتكامل

التاريخ: 2026-09-21. الحالة: خطة عمل مرتبة بالتبعيات؛ ليست تعهدًا بموعد أو ميزانية. تفاصيل التقدم والأدلة في [سجل التنفيذ](execution-status.md). المختبر الأساسي منفذ وبدأ تنفيذ قواعد المحرك؛ التطبيق المتكامل لم يُبن بعد.

## طريقة الإدارة

Product Owner مسؤول عن ترتيب العمل وتثبيت القبول؛ تُسند أدوار التنفيذ والجودة والأمان بحسب الموارد المتاحة. الأرقام معرفات مستقرة وليست وعود ترتيب زمني صارم. يجوز توازي البنود بعد تحقق تبعياتها. التقسيم إلى موجات داخلية يزيل المخاطر قبل دمج الإطلاق الكامل، ولا يعني بيع إصدار MVP.

تعريف إنجاز البند: تنفيذ المخرج، مراجعة مستقلة أو موثقة حيث أمكن، تحقق معايير القبول، ربط الأدلة ومعرف الإصدار، تحديث Markdown، وإظهار القيود المتبقية. كتابة مواصفة لا تُنجز بند تنفيذ. تخضع كل البنود إلى [خطة الجودة](quality-and-release.md) و[نطاق الإطلاق](launch-plan.md).

## موجات التنفيذ الداخلية

1. تعريف وإزالة مخاطر: DL-001 إلى DL-006 وDL-010 وDL-011 وDL-013 وDL-020. المخرج قرارات قابلة للبناء ومختبر؛ ليس منتجًا للبيع.
2. سلامة وتكامل: DL-007 إلى DL-009 وDL-012 وDL-014. لا توسع في الوعود قبل إثبات سلامة الملفات والتسليم.
3. اكتمال تجربة وتجارة: DL-015 إلى DL-023. يجوز التوازي وفق التبعيات، مع استمرار اختبار الانحدار.
4. تأهيل وجذب وإطلاق: DL-024 إلى DL-026. يبقى موعد البيع تابعًا للأدلة والموارد.

## ضبط النطاق والتبعيات الخارجية

القرارات المطلوبة لاحقًا: الاسم والعلامة، جهة البيع ومزود الدفع، أجهزة macOS/Linux الفعلية، حسابات التوقيع والمتاجر، ميزانية الاختبار والدعم. يمكن تقدم المختبر والتوثيق والتصميم دونها؛ لا يمكن اعتبار التوزيع والتجارة مكتملين قبل توافرها.

لا تضاف ميزات إدارة مؤسسية مثل SSO أو سياسات أجهزة مركزية أو SLA تلقائيًا تحت كلمة enterprise. إذا أثبت بحث العملاء حاجة إليها، تُنشأ متطلبات وقبول وتكلفة تشغيل منفصلة قبل إدخالها في النطاق. قوة الإطلاق تقاس بالموثوقية واكتمال الرحلات وجاذبية القيمة المثبتة، لا بعدد البنود.

## سجل تحديث التنفيذ

DL-005 منفذ جزئيًا: نطاقات checked وحالات في الذاكرة وأحداث مربوطة بهوية المهمة والمحاولة، وسياسة تحقق استجابة الاستكمال. نجح 19 اختبار Rust وfmt وClippy. هذه نتيجة الدفعة السابقة للقواعد. أضيف لاحقًا ناقل أحادي الاتصال وتخزين checkpoints واستعادة؛ DL-007 وDL-008 منفذان جزئيًا، ومعايير قبولهما الكاملة لم تُغلق. تفاصيل [بيئة التطوير](development.md) و[حالة التنفيذ](execution-status.md).

قرار المستخدم: واجهة الشراء والدفع والفواتير في الموقع، والتطبيق للتفعيل وعرض الرخصة. يشمل DL-013 رحلة الانتقال للموقع والعودة، ويشمل DL-021 تنفيذ الموقع التجاري والتكامل الخادمي وفق WEB-01 إلى WEB-08 في [الموقع والدفع](web-commerce.md). لا اختيار لمزود أو تنفيذ أو نشر موقع في هذا التحديث.

تفصيل DL-020 وDL-021: تنفيذ مخطط الاستحقاق والتحقق القياسي وإدارة مفاتيح وتفعيل أجهزة مع LIC-01 إلى LIC-07 حسب [تصميم الترخيص](licensing-and-tamper-resistance.md). اختبارات المؤسسات مشروطة بإضافة B2B. يرتبط LIC-08 بـDL-022 الخاص بالتوزيع والتحديث. جميعها مخططة؛ لا يكفي نجاح مختبر HTTP لاجتيازها.

طريقة التنفيذ والمراجعة تتبع [معايير الهندسة](engineering-standards.md) و[سياسة المراجعة](review-policy.md)؛ مقاومة الكراك لا تستبدل سلامة الملفات أو تتحكم في كتابة البايتات داخل محرك النقل.
