# مراجعة إدارة مهام التنزيل

التاريخ: 2026-09-21. المراجع: وكيل Engineering وSecurity مستقل عن منفذ مدير المهام. النطاق: القبول والطوابير والتزامن والإيقاف المؤقت والاستئناف وإغلاق المالك. هذه مراجعة داخلية وليست اعتماد إطلاق.

## شروط القبول

- مدير واحد يملك الحالة المرجعية؛ الواجهة تقرأ snapshots منقحة وترسل أوامر محددة. لا روابط أو بيانات طلب أو مسارات في إشعارات التقدم.
- عدد المهام والتشغيل المتزامن وقناة الأوامر وأحجام المدخلات محدودة؛ تحفظ آخر لقطة بدل تكديس أحداث تقدم غير محدودة.
- الإيقاف المؤقت يطلب الإلغاء التعاوني وينتظر انتهاء النقل وعامل القرص وإغلاق التخزين قبل إقرار Paused أو السماح باستئناف جديد.
- نجاح التحقق والنشر المتزامن مع طلب الإيقاف يظل Completed؛ الطلب المتأخر لا يحول ملفًا منشورًا إلى تنزيل جزئي.
- إغلاق المدير يوقف قبول مهام جديدة ويطلب إلغاء العاملين وينتظر النتائج. إسقاط handle دون shutdown لا يساوي إغلاقًا مكتملًا؛ بقاء runtime شرط لاستمرار التنظيف الخلفي.
- الأخطاء وpanics في العمال تنسب إلى المهمة الصحيحة؛ لا تحرير خانة التزامن قبل انتهاء العامل. لا إلغاء قسري لعامل القرص لمجرد إيقاف future.
- الهوية غير سرية ومستقرة داخل عمر المدير؛ لا إعادة استعمال تسمح لنتيجة محاولة قديمة بتعديل محاولة جديدة.
- منع قبول مهمتين لنفس مجلد التخزين بعد توحيد المسار؛ قفل Store يبقى خط دفاع مستقلًا. لا حذف جزئيات أو ملفات نهائية بسبب إيقاف أو فشل.

## الحدود المطلوبة في هذه الدفعة

الطابور في الذاكرة فقط؛ الاستعادة التلقائية لقائمة المهام بعد إعادة تشغيل التطبيق غير منفذة. المدير API محلي لمستدعٍ موثوق، وليس نقطة قبول IPC أو إضافة متصفح. لا يضيف مصادقة أو ترخيصًا أو تخزين أسرار. الإغلاق الصريح المنتظر هو عقد السلامة؛ إنهاء العملية أو تدمير Tokio runtime قبل انتهاء shutdown يترك الاستعادة للتخزين المتين ولا يضمن إكمال الإيقاف.

## نتيجة المراجعة

اكتمل فحص الكود المستقل وأغلقت الملاحظات الموضحة أدناه. نتائج تشغيل workspace مرجعها سجل التنفيذ؛ قائمة الشروط وحدها لا تثبت تأهيل الإصدار.

## نتائج فحص التنفيذ

فُحص `crates/download-engine/src/manager.rs` وتغييرات إشعارات checkpoint في الناقل واختبارات `tests/manager.rs` مستقلًا عن التنفيذ. لا توجد تبعيات جديدة في هذا التغيير.

الملاحظات المغلقة:

1. كان إقرار pause يعيد نجاحًا حتى إذا انتهى العامل بفشل حفظ checkpoint. أصبح يعيد `WorkerFailed` وتبقى الفئة المنقحة الدقيقة في `Failed` داخل snapshot. لا تتحول مشكلة التخزين إلى Paused ناجحة.
2. توحيد مسار المجلد وحده لم يمنع أسماء Windows غير الموجودة مثل `job.` و`job ` من الاختلاف في مفتاح الطابور رغم احتمال تطابق وجهة النظام. أصبحت نهايات النقطة والمسافة وأسماء الأجهزة والمحارف الملتبسة مرفوضة؛ أضيف اختبار خاص بـWindows.
3. حُددت أحجام الرابط والاسم والمسار وخيارات الموارد قبل إدخال الأمر إلى القناة، بجانب حدود عدد المهام والأوامر والتشغيل. لا يعتمد حد الذاكرة على عدد المهام وحده.
4. أضيف إيصال تقدم بعد نجاح checkpoint النهائي للإلغاء أو الفشل الشبكي، وبعد قراءة تقدم محفوظ صالح. لا يصدر الإيصال إذا فشل عامل القرص.

الحدود المفحوصة: حتى 32 عاملًا و1024 سجل مهمة وقناة أوامر سعتها 64، مع لقطة watch أخيرة وتحديث تقدم ذري بدل طابور غير محدود. العامل ينتهي ويحرر التخزين قبل انضمام نتيجته وتحرير خانة التزامن. يتتبع JoinSet هوية العامل لربط فشله بالمهمة الصحيحة. لا يحتفظ actor بمرسل أوامر يمنع اكتشاف إسقاط المالك، ولا يستعمل abort في مسار الإغلاق المعتاد.

نتيجة النقل الناجحة تتقدم على طلب pause متأخر؛ اختُبر هذا التصنيف حتميًا في وحدة، وليس بادعاء حملة سباقات شاملة. إلغاء منتظر يتبعه خطأ تخزين يبقى Failed. نجاح shutdown يعني انتهاء العمال؛ يتعين الاحتفاظ باشتراك snapshots لفحص أي إخفاق في حفظ حالة إحدى المهام.

الاختبارات المفحوصة تشمل خمس تجارب نقل فعلية: FIFO مع pause/resume والتحقق من البايتات، إغلاق مع بقاء مهمة في الطابور، إسقاط المالك ثم إثبات تحرير قفل Store، وحد عاملين مع مهمة ثالثة منتظرة، وإيقاف مهمة منتظرة يمنع طلب الشبكة حتى استئناف صريح. اختبارات الوحدات تفحص حدود القبول وإخفاء المدخلات وحالات الإكمال/الفشل وأسماء Windows الملتبسة. المراجع فحص الاختبارات ولم يشغل Cargo بالتوازي؛ أرقام النجاح النهائية تسجل في [سجل التنفيذ](execution-status.md).

الحكم النصي بعد إعادة الفحص: لا ملاحظة مانعة متبقية ضمن نطاق المدير الداخلي الحالي، بشرط نجاح الفحوص التشغيلية المسجلة منفصلًا. لا يغطي هذا الحكم ثبات الطابور بعد إعادة تشغيل التطبيق أو مصادقة IPC أو الترخيص أو إطلاق المنصات الأخرى.

## قيود متبقية

توحيد المسار ينفذ في عامل blocking لكن actor ينتظر نتيجته؛ filesystem بطيء أو غير مستجيب قد يؤخر معالجة pause/shutdown. هذه واجهة داخلية لمسارات محلية موثوقة ولا يوجد ضمان زمني للإلغاء. التوحيد ليس حاجزًا ضد تبديل مسارات من عملية خبيثة بنفس المستخدم؛ قفل Store وفحوصه مستقلان. لا تمنع مقارنة Windows بالحروف الصغيرة كل حالات الاسم البديل، وقد ترفض أسماء منفصلة في مجلد حساس لحالة الأحرف تحفظًا.

الهوية متزايدة داخل عمر المدير ولا يعاد استعمالها فيه؛ ليست هوية دائمة أو صلاحية وصول. المهام المكتملة والفاشلة تستهلك الحد حتى نهاية عمر المدير؛ الحذف والأرشفة والاستعادة الدائمة لم تنفذ. طبقة المدير لها حالة تنسيق مجملة فوق حالات النقل الداخلية؛ لا تدعي Running أنها تعني انتقال البايتات حاليًا، فقد تشمل التحقق والنشر.
