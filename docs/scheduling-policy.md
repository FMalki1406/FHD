# أولوية المهام وحد التزامن لكل أصل

وحدة داخلية في مدير المهام. المقصود بالأصل هنا مجموعة scheme وhostname والمنفذ الفعلي؛ ليست شركة الاستضافة أو عنوان IP أو نطاقًا رئيسيًا يجمع كل subdomains.

## سلوك الطابور

- start_with_limits يحدد حدًا عالميًا وحدًا لكل أصل وعدد المهام. start القديم يبقى متوافقًا؛ حد الأصل فيه يساوي الحد العالمي، فلا يتغير سلوك المتصل الحالي بصمت.
- الأولوية Low أو Normal أو High. enqueue العادي يستخدم Normal. الأعلى أولوية يُختار من المهام القابلة للتشغيل فقط، مع FIFO عند التساوي.
- امتلاء خانات أصل ما لا يمنع تشغيل مهمة لأصل آخر، حتى لو كانت أولويتها أقل. لا تُحجز خانة عالمية لمهمة لا تستطيع البدء.
- تغيير الأولوية مسموح للمنتظرة أو المتوقفة أو الفاشلة، ولا يوقف تنزيلًا جاريًا. عند التساوي يظل موضع الطابور كما هو، والاستئناف يعود إلى نهايته.
- المهام التي تتوقف ما زالت تستهلك خانتها حتى تنتهي كتابة العامل ويصل تأكيد انتهائه. فشل العامل يحرر الخانة بعد جمع نتيجته، لا بمجرد إرسال الإلغاء.

## حدود وقرارات

التنفيذ الحالي يحافظ على سياسة التحويل داخل الأصل نفسه في ناقل HTTP؛ السماح بتحويلات إلى أصل آخر لاحقًا يحتاج إعادة مراجعة حجز الخانات. أسماء DNS مختلفة قد تشير للخادم نفسه، ومنافذ مختلفة تعتبر أصولًا مختلفة. لا يدعي هذا الحد حماية من SSRF أو منع إساءة طلبات خصم متعمد؛ المدخل محلي موثوق فقط.

هذه حدود عدد مهام نشطة، وليست حدود عدد TCP connections الفعلية أو معدل الطلبات أو عرض النطاق. لا تقسيم متعدد الاتصالات لملف واحد بعد. تعاقب مهام قصيرة قد يرسل طلبات كثيرة رغم الالتزام بالتزامن؛ rate limiting وbackoff سياسة مستقلة لاحقًا.

الأولوية الصارمة قد تؤخر مهمة منخفضة إذا ظل وصول مهام أعلى مستمرًا. لم ننفذ aging أو وزنًا لتقاسم الموارد؛ عدد المهام محدود حاليًا لكن لا وعد أقصى انتظار. بيانات الأصل تبقى داخل المدير في الذاكرة ولا تدخل snapshots أو رسائل الأخطاء. الأولويات والطابور لا يُحفظان بين تشغيلات التطبيق بعد.

المراجع: [مدير المهام](task-manager.md)، [مراجعة الجدولة](scheduler-review.md)، [نتائج التنفيذ](execution-status.md).

الحدود تخص كل Manager على حدة؛ إنشاء مدير آخر أو استدعاء download مباشرة لا يشارك الحصة. لا يجوز وصفها بحدود التطبيق الشاملة قبل أن يمر كل مدخل عبر مدير واحد معتمد. اختيار المهمة محدود بسقف 1024 مهمة لكنه يفحص قائمة المهام أثناء الاختيار؛ لم تُقَس كلفة الجدولة تحت حمل كبير بعد.
