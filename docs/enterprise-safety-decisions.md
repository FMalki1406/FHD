# قرارات سلامة إعادة بناء المحرك

التاريخ: 2026-09-21. تنفيذ الأساس يجري وفق enterprise-engine-architecture.md مع التصحيحات الملزمة أدناه. إنشاء وحدات جديدة لا يعني اكتمال إعادة البناء أو تأهيل الأداء. نتائج الاختبار يسجلها الوكيل الرئيسي بعد تشغيله؛ لم يشغل وكيل هذا المستند Cargo.

## تصحيحات معمارية ملزمة

1. **الحجز المسبق:** لا استخدام SetFileValidData. تجاوز تصفير المساحة قد يكشف بيانات قرص سابقة ويحتاج صلاحية غير مناسبة للتنزيلات. نحجز/نمدد الملف بآلية آمنة للمنصة ونقيس sparse وpreallocation دون اعتبار طول الملف دليل كتابة أو متانة. [تحذير Microsoft الرسمي](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfilevaliddata).
2. **تقسيم المقاطع أثناء العمل:** لا نقل ملكية أو تقليص نطاق in-flight دون بروتوكول claim/revoke/ack وجيل ورقم محاولة. عامل قديم لا يكتب ذيلًا أعيد إسناده؛ split/steal ليس تغيير رقم end فقط. نقطة EOF يجب أن تطابق النطاق المسند والتأطير، ولا تعني انتهاء الملف ما دام مخطط النطاقات غير مكتمل.
3. **استكمال مجهول الحجم:** ETag بمفرده لا يثبت أن اتصالًا مقطوعًا انتهى. يحتفظ المسار الحالي بالأجزاء دون إلحاق تلقائي. توسيع الاستكمال يحتاج طلب Range متحققًا وتحديد إجمالي التمثيل والتحقق من كل receipt وحد النهاية، أو بدء مورد جديد؛ لا نشر على TCP EOF مبهم.
4. **ميزانية الذاكرة:** 64 MiB افتراضي لبايتات buffers التي يملكها مسار البيانات. ليس حد RSS للعملية أو ذاكرة TLS/HTTP/OS أو هياكل السجل. يجب تحديد هل يشمل buffers قيد الشبكة والانتظار والكتابة، وامتلاك permits طوال عمر البايتات؛ الحساب بالصفوف وحده لا يكفي. الزيادة حتى 512 MiB إعداد صالح وليست وعد أداء.
5. **Client pooling:** مشاركة Client داخل profile سياسة اتصال ثابتة. proxy وCA وmTLS وحساب المؤسسة يحددون هوية pool؛ لا global singleton يجمع سياسات متناقضة. الرؤوس الحساسة per-request، ورفض تخفيض TLS وعدم الرجوع direct صامتًا عند فرض proxy شرطان مستقلان.
6. **SecretRef:** المرجع في جدول لا يشفر بقية metadata. أسماء الملفات والمسارات وETag وسياق الرابط قد تكشف بيانات حساسة؛ يلزم inventory وحقول سرية أو حماية ملائمة، ولا يعلن أن استبدال URL بمرجع يلغي كل حاجة لحماية القاعدة. المراجع ليست أسرار ترخيص ولا تفويضًا بذاتها.
7. **النشر:** لا check-absence ثم rename بديلًا لـno-replace. دعم junction وOneDrive يحتاج handle مثبتًا وسياسة reparse tags؛ لا إلغاء شامل للحماية. الكود الداخلي الحالي يحتفظ بقيوده إلى تنفيذ المحول واختباره.

## fhd-config: المنفذ

وحدة بلا I/O، إعداداتها الفعالة وحقول patch خاصة. Setting يحدد حدودًا ثابتة: مهام 1–32، اتصالات لكل مهمة 1–16، لكل أصل 1–32، buffers من MiB واحد حتى 512 MiB وافتراضي 64 MiB، تحويلات حتى 20، ومهل اتصال/TLS/قراءة وTTL ضمن حدود معلنة في الكود. استقلال حصة المهمة عن الأصل مقصود: المجدول يطبق التقاطع الفعلي ولا يشترط أن يكون الحد الخاص بالمهمة أصغر من حصة الأصل.

تنتج resolve لقطة جديدة من defaults ثم user ثم enforced مع Source لكل قيمة. patch غير صالح لا ينتج EffectiveConfig جديدًا؛ لا تعديل جزئي لحالة حية. المتحكم الموثوق وحده يحدد مصدر policy؛ لم تنفذ قارئات GPO/MDM أو اشتراكات تطبيق حي بعد.

NetworkPolicy يمثل Direct/System/Proxy. ProxyEndpoint محلل عبر url 2.5.8؛ يقبل HTTP/HTTPS فقط بلا userinfo أو query أو fragment أو path، وDebug/Display محجوبان. لا كلمة مرور داخل إعداد endpoint؛ التعريف intent وليس تنفيذ proxy/PAC/WPAD أو تفويض تجاوز TLS. النظام غير المدعوم يجب أن يفشل بدل تجاهل السياسة. Direct الافتراضي اختيار صريح للأساس؛ يتغير عند اعتماد سياسة المنتج، وليس محاكاة إعدادات النظام.

## fhd-telemetry: المنفذ

أنواع SecretUrl/Credential/UserPath محجوبة عبر Debug وDisplay، وحدود أطوال مع Zeroizing للنسخة المملوكة؛ expose واضح للمحول الموثوق. هذه أغلفة منع طباعة وليست محلل URL أو حارس filesystem أو ضمان مسح كل نسخة سبق أن أنشأها caller.

Event ذو codes ثابتة وحقول رقمية معروفة فقط، بلا نص حر أو URL أو path أو رأس. Recorder حلقة ذاكرة من 1 إلى 4096 سجلًا؛ يزيل الأقدم عند الامتلاء ويحصي الإزاحة، والعدادات ذات 14 label ثابتًا بلا labels مشتقة من job أو origin. التسلسل يفشل صراحة عند overflow، والعدادات الأخرى saturating. الإيقاف يمنع الأحداث اللاحقة ولا يمحو السابقة؛ clear_records يمسحها صراحة.

ينبعث الحدث إلى tracing بالفعل، مع اختبار subscriber يلتقط الحقول ويتحقق من التنقيح. لا subscriber ملفي عام ولا دوران ملفات ولا خدمة رفع ولا حزمة دعم أو crash reporter منفذة. سياسة config الخاصة telemetry تتعلق بالمراقبة المحلية؛ لا تعني الموافقة على إرسال بيانات. كل مكون يتجاوز facade ويكتب tracing مباشرة يظل مسؤولًا عن الحجب؛ لا ندعي أن مكتبة تمنع طباعة String خام في بقية المشروع.

## مراجعة اعتماديات الأساس

استخدمت نسخًا موجودة في Cargo.lock وcache المحلي: url 2.5.8 (MIT أو Apache-2.0)، tracing 0.1.44 (MIT) وzeroize 1.9.0 (MIT أو Apache-2.0). tracing يعمل بميزات std فقط دون default attributes لتجنب إضافة proc macro غير موجود في cache. لم يطلب هذا العمل تنزيل dependency أو تشغيل شبكة أو تعديل ملف القفل من الوكيل الفرعي. هذه مراجعة نطاق واستعمال، وليست فحص advisories شاملًا.

اختبارات الوحدتين تغطي أولوية السياسة وحدود القيم وعدم التطبيق الجزئي ورفض proxy secrets، وDebug/Display الحقيقي، وحد الحلقة وثبات cardinality وتسلسل الأحداث وإيقاف التسجيل وحقول tracing الفعلية. إدخالهما workspace والتحقق الموحد مسؤولية composition root.

## مراجعة مستقلة لطبقة التطبيق

راجعت Security حالات الاستخدام وtestkit التي نفذها الوكيل الرئيسي. ReceiptKey مقيد بـPrincipal، والمقارنة تشمل JobSpec الأصلي بشرط أن تكون SourceRef وDestinationRef ربطًا immutable لا يعاد استعماله لمورد/جلسة أخرى. استبدال بيانات المرجع في مكانه ينقض منع التكرار؛ ليس المرجع وحده آلية تشفير أو تفويض.

المعاملة تجمع Job وReceipt، والتعارض يعاد حله بقراءة الإيصال. فقد رد commit لا يعالج بحذف المهمة أو تصنيع نجاح؛ يعيد العميل المفتاح نفسه. MemoryRepository fake محدود للاختبار، لا مخزن إنتاجي دائم، وAllow/Deny أدوات اختبار لا رخصة مدفوعة منفذة.

كشفت المراجعة أن اشتراط الاستحقاق الجديد قبل قراءة إيصال قديم كان يمنع مصالحة قبول سابق بعد انتهاء الرخصة. عولج الترتيب: تفويض حالي أولًا، ثم replay للإيصال الموجود، ثم استحقاق لإنشاء مهمة جديدة فقط. أضيف اختبار يثبت استعادة نفس JobId مع استحقاق منتهٍ ورفض مهمة جديدة. التفويض المنتهي لا يسمح قراءة إيصال، حتى إذا ظل الترخيص صالحًا. هذا قرار تجربة وسلامة للطلبات التي قبلت سابقًا، وليس إعفاءًا من تفويض الخدمة.

## مراجعة الدومين بعد الإصلاح

راجعت Security Job وSegmentMap وRetryPolicy بعد ملاحظات Engineering وإعادة الفحص. تذاكر checkpoint غير قابلة للنسخ عبر API العام، وتطابق المهمة والجيل والتسلسل واختيار النطاقات ومحاولاتها. أزيل Clone العام من التجمعات التي تحمل سلطة العمل. Written أو إقرار sync وحده لا يزيد التقدم المتين، ولا يسمح التحقق النهائي قبل اكتمال Durable.

كشفت إعادة المراجعة أن Retry/RequireAction كانا يسمحان مغادرة النقل مع checkpoint معلق، فتتعذر معالجته عبر واجهة الخريطة في الحالة الجديدة. عولج الحارسان وأضيف اختبار يمنع الانتقال حتى تصريف checkpoint. استبدال generation في SegmentMap يرفض العمال النشطين وcheckpoint المعلق؛ SourceChanged/Integrity يحتاجان استبدال تمثيل صريحًا بدل إعادة محاولة تحت الجيل القديم.

abandon/discard checkpoint مدخل للمحول الموثوق بعد إيقاف استخدام التذكرة القديمة ومصالحة القرص، وليس إثباتًا أن مصالحة فعلية حدثت. وبالمثل acknowledge_sync/commit إقرار من محول يملك الدليل؛ الدومين النقي لا يستطيع إثبات fsync أو transaction بنفسه. منع عامل قديم من كتابة ملف جديد يحتاج حارس generation وإغلاق/drain في الكاتب المستقبلي، لا يكفي رفض حدث حالته بعد كتابة خاطئة.

لا ملاحظة شفرة مانعة متبقية ضمن أساس الدومين وحالات الاستخدام المفحوصة بعد هذه الإصلاحات. ما زالت hashes لكل extent والتحقق الفعلي من الشبكة ومخزن النطاقات والكاتب والمحولات الدائمة غير منفذة في المسار الجديد. لا تُحوّل اختبارات الدومين إلى ادعاء نجاة من قتل عملية أو فصل طاقة، ولا يزال اختبار وتشغيل الوكيل الرئيسي شرطًا منفصلًا.
