# تأهيل المحرك والتحقق عبر الأنظمة

الحالة: أضيف تعريف GitHub Actions وتجربة نقل اختيارية. وجود ملف workflow لا يعني تشغيله أو نجاحه، ولا يعد اعتمادًا تجاريًا. الدليل المحلي المتاح Windows؛ نتائج Linux وmacOS **معلقة حتى تشغيل المصفوفة وقراءة نتائجها**.

## التحقق الآلي المعد

ملف `.github/workflows/engine.yml` يعرّف Windows 2022 وUbuntu 24.04 وmacOS 14، مع Rust 1.98.1 وNode 22.13.1 المثبتين للإعادة. ينفذ التنسيق وClippy بلا تحذيرات واختبارات workspace وبناء أداة التنزيل واختبارات المختبر والبرنامج الفعلي. اختبار شهادة TLS المحلي يعمل على Windows فقط باستخدام PowerShell 7.

صلاحيات سير العمل قراءة المستودع فقط؛ لا أسرار منتج أو توقيع أو رفع حزم أو نشر. لا تحفظ بيانات اعتماد checkout في نسخة العمل. مراجع Actions مثبتة بمعرف commit كامل: [checkout v4.2.2](https://github.com/actions/checkout/commit/11bd71901bbe5b1630ceea73d27597364c9af683) و[setup-node v4.4.0](https://github.com/actions/setup-node/commit/49933ea5288caeca8642d1e84afbd3f7d6820020). تثبيت الإصدارات ليس مراجعة ثغرات شاملة، وصور المضيف بأسمائها تتلقى تحديثات؛ لا ندعي إعادة إنتاج بتطابق ثنائي.

الطابور الدائم يعتمد DPAPI على Windows؛ اختباراته ذات ملف Windows صريح. على الأنظمة الأخرى يختبر محول الأسرار رفض `protect` و`unprotect` بـ`UnsupportedPlatform`، دون رجوع لنص واضح. إتمام النقل على Linux أو macOS لا يعني أن حفظ الطابور مشفرًا أصبح مدعومًا هناك.

## حمل اختياري مضبوط

اختبار `bounded_64_mib_chunked_workload` غير مشغّل افتراضيًا. يولد خادم loopback ملفًا قدره 64 MiB بإعادة استعمال كتلة 16 KiB، ويكتب الناقل تدريجيًا مع checkpoints كل MiB، ثم يتحقق من SHA-256 بقراءة محدودة الذاكرة. لا يبني مصفوفة بحجم الملف، ويزيل دليل الاختبار عند انتهائه. سقف زمن التجربة ثلاث دقائق.

تشغيله على بيئة Rust المضبوطة:

```text
cargo test -p download-engine --test unknown_length bounded_64_mib_chunked_workload --locked -- --ignored --exact
```

على Windows باستخدام أدوات المستودع المحلية:

```powershell
& .\tools\rust.ps1 -CargoArguments @('test','-p','download-engine','--test','unknown_length','bounded_64_mib_chunked_workload','--locked','--offline','--','--ignored','--exact')
```

يتوفر اختيار `run_extended` عند التشغيل اليدوي لسير العمل. هذه تجربة نقل متوسطة الحجم، وليست اختبار تشغيل لأيام أو إثبات عدم تسرب الذاكرة أو قياسًا تنافسيًا للأداء.

## بوابات لم تغلق

| البوابة | الدليل المطلوب قبل الإطلاق |
| --- | --- |
| الأنظمة الثلاثة | تشغيل المصفوفة الناجح وربط النتائج بإصدار المصدر، ثم أجهزة فعلية للمثبت والتحديث |
| الملفات الضخمة | عدة GiB وأحجام تتجاوز 4 GiB مع إلغاء واستكمال وتحقق، على أنظمة الملفات المدعومة |
| مدة التشغيل | ساعات وأيام مع مراقبة ذاكرة ومقابض ملفات واتصالات وطوابير مستقرة |
| الأعطال المادية | امتلاء قرص فعلي، فصل جهاز تخزين، إعادة تشغيل قسرية وفصل طاقة في بيئة اختبار |
| TLS | شهادات صحيحة ومنتهية واختلاف الاسم وسلاسل ثقة متعددة وHTTP/2 مؤطر |
| الاستعادة | قتل المدير أثناء حفظ الطابور وأثناء نقل متعدد، مع مقارنة الملفات واللقطات |
| التوزيع | مثبت وتوقيع وتحديث موثوق واختبار إزالة وتراجع؛ جميعها خارج هذا workflow |

تضاف نتائج التشغيل الفعلية إلى `docs/execution-status.md`؛ لا تستبدل هذه الخطة سجل الأدلة.

الدليل المحلي المسجل: نجحت تجربة 64MiB الاختيارية في 28.19 ثانية على Windows ضمن هذه الدفعة، مع بقية 119 اختبار Rust و40 اختبار Node/TLS/مختبر. النتيجة مرتبطة بكود هذه الدفعة في سجل Git؛ المصفوفة البعيدة تظل بحاجة نتيجة مستقلة بعد رفع workflow.
