# تأهيل المحرك والتحقق عبر الأنظمة

نطاق الوثيقة: خطة تأهيل وسجل تجربة للمحرك القديم download-engine/fhd-transfer؛ حالة المحركين الراهنة في [سجل التطبيق](enterprise-implementation-status.md). النتيجة التاريخية للكود ef08174: نجحت مصفوفة GitHub Actions على Windows 2022 وUbuntu 24.04 وmacOS 14، وتجربة نقل64MiB محليًا على Windows. هذه نتيجة تلك النسخة وليست اعتمادًا للحالة الحالية أو مثبت أو جاهزية تجارية. [نتيجة التشغيل التاريخية](https://github.com/FMalki1406/FHD/actions/runs/35627953607).

## التحقق الآلي المعد

ملف `.github/workflows/engine.yml` يعرّف Windows 2022 وUbuntu 24.04 وmacOS 14، مع Rust 1.98.1 وNode 22.13.1 المثبتين للإعادة. ينفذ التنسيق وClippy بلا تحذيرات واختبارات workspace وبناء أداة التنزيل واختبارات المختبر والبرنامج الفعلي. اختبار شهادة TLS المحلي يعمل على Windows فقط باستخدام PowerShell 7.

صلاحيات سير العمل قراءة المستودع فقط؛ لا أسرار منتج أو توقيع أو رفع حزم أو نشر. لا تحفظ بيانات اعتماد checkout في نسخة العمل. مراجع Actions مثبتة بمعرف commit كامل: [checkout v5.1.0](https://github.com/actions/checkout/commit/fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09) و[setup-node v5.0.0](https://github.com/actions/setup-node/commit/a0853c24544627f65ddf259abe73b1d18a591444). هذان الإصداران يستخدمان Node.js 24 **لتشغيل الإجراءين**؛ أما `node-version: 22.13.1` فيختار Node.js لاختبارات المشروع. عُطّل تخزين الحزم التلقائي في `setup-node` لأن هذه المهمة لا تحتاجه. تثبيت الإصدارات ليس مراجعة ثغرات شاملة، وصور المضيف بأسمائها تتلقى تحديثات؛ لا ندعي إعادة إنتاج بتطابق ثنائي. نتيجة CI على الرأس الذي يحمل الترقية تُسجّل منفصلةً حين تصدر؛ إزالة التحذير لم تُقَس بعد.

الطابور الدائم **للمحرك القديم** يعتمد DPAPI على Windows؛ اختباراته ذات ملف Windows صريح. على الأنظمة الأخرى يختبر محول الأسرار رفض `protect` و`unprotect` بـ`UnsupportedPlatform`، دون رجوع لنص واضح. المحرك الجديد له SQLite WAL ومخزن مراجع مستقل كما يوضح [المستودع](enterprise-persistence.md)، ولا يعني ذلك وجود vault نظام أو تشفير طابور القديم على الأنظمة الأخرى.

## حمل اختياري مضبوط

اختبار `bounded_64_mib_chunked_workload` غير مشغّل افتراضيًا. يولد خادم loopback ملفًا قدره 64 MiB بإعادة استعمال كتلة 16 KiB، ويكتب الناقل تدريجيًا مع checkpoints كل MiB، ثم يتحقق من SHA-256 بقراءة محدودة الذاكرة. لا يبني مصفوفة بحجم الملف، ويزيل دليل الاختبار عند انتهائه. سقف زمن التجربة ثلاث دقائق.

تشغيله على بيئة Rust المضبوطة:

```text
cargo test -p download-engine --test unknown_length bounded_64_mib_chunked_workload --locked -- --ignored --exact
```

على Windows باستخدام أدوات المستودع المحلية:

```powershell
& .\tools\rust.ps1 -CargoArguments @('test','-p','download-engine','--test','unknown_length','bounded_64_mib_chunked_workload','--locked','--offline','--','--ignored','--exact')
```

يتوفر اختيار `run_extended` عند التشغيل اليدوي لسير العمل. هذه تجربة نقل متوسطة الحجم، وليست اختبار تشغيل لأيام أو إثبات عدم تسرب الذاكرة أو قياسًا تنافسيًا للأداء.

## بوابات لم تغلق

| البوابة | الدليل المطلوب قبل الإطلاق |
| --- | --- |
| الأنظمة الثلاثة | تشغيل المصفوفة الناجح وربط النتائج بإصدار المصدر، ثم أجهزة فعلية للمثبت والتحديث |
| الملفات الضخمة | عدة GiB وأحجام تتجاوز 4 GiB مع إلغاء واستكمال وتحقق، على أنظمة الملفات المدعومة |
| مدة التشغيل | ساعات وأيام مع مراقبة ذاكرة ومقابض ملفات واتصالات وطوابير مستقرة |
| الأعطال المادية | امتلاء قرص فعلي، فصل جهاز تخزين، إعادة تشغيل قسرية وفصل طاقة في بيئة اختبار |
| TLS | شهادات صحيحة ومنتهية واختلاف الاسم وسلاسل ثقة متعددة وHTTP/2 مؤطر |
| الاستعادة | قتل المدير أثناء حفظ الطابور وأثناء نقل متعدد، مع مقارنة الملفات واللقطات |
| التوزيع | مثبت وتوقيع وتحديث موثوق واختبار إزالة وتراجع؛ جميعها خارج هذا workflow |

تضاف نتائج التشغيل الفعلية إلى `docs/execution-status.md`؛ لا تستبدل هذه الخطة سجل الأدلة.

الدليل المحلي المسجل: نجحت تجربة 64MiB الاختيارية في 28.19 ثانية على Windows ضمن هذه الدفعة، مع بقية 119 اختبار Rust و40 اختبار Node/TLS/مختبر. النتيجة مرتبطة بكود هذه الدفعة في سجل Git؛ نجحت المصفوفة البعيدة لاحقًا للكود ef08174 في التشغيل المرتبط أعلاه.
