# الأمن والاعتمادية

التاريخ: 2026-09-21. الحالة: متطلبات تصميم وبوابات إصدار مقترحة؛ لا تمثل شهادة أو اختبارًا منفذًا. النطاق: تطبيق التنزيل وإضافاته وتوزيعه والخدمة التجارية. يقرأ مع [المعمارية](architecture.md).

## الأصول وحدود الثقة

الأصول: الملفات الموجودة للمستخدم، الأجزاء المحفوظة، بيانات الجلسة، الروابط الموقعة، بيانات الحساب والاستحقاق، سلامة التحديث، وخصوصية سجل النشاط. مصادر البيانات غير الموثوقة تشمل صفحة الويب، خادم التنزيل، أسماء الملفات، manifest الوسائط، امتدادًا منتحلًا، ملف إعدادات مستوردًا وملف دعم واردًا.

حدود الثقة: صفحة ← إضافة ← Native Host ← محرك؛ واجهة WebView ← أوامر أصلية؛ محرك ← filesystem؛ تطبيق ← خدمة تجارية؛ حزمة تحديث ← توقيع موثوق. حيازة مهاجم صلاحيات administrator أو حساب المستخدم نفسه قد تمكنه من تجاوز أجزاء الحماية المحلية؛ لا نسوق المنتج كحماية من اختراق نظام التشغيل.

## نموذج التهديد والضوابط

| التهديد | الضابط المطلوب | دليل القبول |
| --- | --- | --- |
| صفحة تصدر أوامر أو حقن في اسم ملف | أسماء كنص بلا HTML؛ أوامر معرفة ومحددة؛ CSP وصلاحيات WebView دنيا | حمولة XSS لا تنفذ ولا تصل لكتابة أو shell |
| انتحال إضافة/عميل IPC | allowlist أصل الإضافة، صلاحيات قناة محلية، تحقق طرف ورسالة وإصدار | رفض أصل غير معتمد ومستخدم آخر ورسالة مجهولة |
| traversal أو symlink/reparse point | تنظيف الاسم، رفض المسارات المطلقة والأسماء المحجوزة، فتح آمن بالنسبة لدليل مختار وإعادة التحقق عند النشر | لا كتابة خارج الوجهة حتى في سباق تبديل الرابط |
| كتابة فوق ملفات المستخدم | إنشاء حصري وحجز اسم ونشر no-replace؛ حذف الملفات المملوكة للمهمة فقط | ملف collision يبقى byte-identical |
| SSRF/طلب شبكي خفي عبر صفحة | استيراد بتفاعل واضح، سياسات مستقلة للعناوين الخاصة وloopback وlink-local، إعادة فحص كل تحويل وDNS | طلب صفحة عام لا يصل لعنوان داخلي محظور بعد redirect أو DNS rebinding |
| قطع الوصول للمصادر الداخلية المشروعة | السماح بسياسة صريحة للمستخدم/المؤسسة؛ لا اعتبار كل شبكة خاصة خبيثة | تنزيل intranet يعمل فقط ضمن السياسة الموثقة |
| تسريب الجلسة عبر redirect | قصر الأسرار على origin وسياق الاستخدام؛ تخزين نظامي محمي | أصل ثان لا يستقبل Authorization/Cookie |
| تسريب روابط أو بيانات عبر الدعم | تنقيح query وheaders ومسارات حساسة؛ معاينة حزمة الدعم قبل تصديرها | canary secrets غير موجودة في log أو crash report أو telemetry |
| خادم يخلط أجزاء موارد | جيل تمثيل ثابت وفحوص Range والهوية والبصمات | حالات خادم متناقضة تتوقف دون نشر ملف مختلط |
| استنزاف قرص/ذاكرة/اتصالات | طوابير محدودة وسقوف لكل مضيف/مهمة/دفعة، إيقاف كتابة عند مساحة حرجة | حمل خبيث لا يسبب نموًا غير محدود ولا يعلق الواجهة |
| ملف وسائط يستغل parser | عامل معزول، مهلة وحدود موارد، ملفات دخول محددة، لا shell interpolation | crash للعامل لا يسقط المحرك؛ escape tests لكل منصة |
| ملف منزل ضار | لا تشغيل تلقائي؛ حفظ إشارات مصدر الإنترنت/الحجر المتاحة للنظام واختبارها | فتح الملف إجراء مستخدم؛ حماية النظام لا تتجاوز لتجميل التجربة |
| تحديث أو تبعية مخترقة | توقيع حزم وmanifest، فحص إصدار ومنع downgrade غير مصرح، مفاتيح منفصلة عن CI العادي | توقيع معدل/مفتاح خاطئ/manifest قديم يرفض |
| اختراق خدمة الترخيص | صلاحيات حدية، فصل الأسرار، rate limits ومراجعة تغييرات الاستحقاق | فشل الخدمة لا يرسل ملفات أو يفسد مهمة محفوظة |

ضوابط IPC المقترحة تطبق فوق آلية المتصفح، وليست ضمانًا توفره وحدها. المرجع: [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging). يجب مراجعة Firefox ومتطلبات المتاجر ضمن تنفيذ الإضافة قبل إعلان الدعم.

## سياسة خصوصية قابلة للتنفيذ

- تنزيل محلي بلا رفع URLs أو أسماء ملفات أو تاريخ تصفح لأغراض الترخيص أو التحليل.
- telemetry تشخيصي اختياري، مع قائمة حقول موثقة ومعرفات عشوائية محدودة العمر وسياسة احتفاظ؛ لا أسرار في crash dumps افتراضيًا.
- إلغاء جلسة أو حذف حساب يعالج بيانات الخدمة وفق سياسة موثقة؛ لا يحذف تنزيلات المستخدم محليًا ضمنيًا.
- حزمة الدعم تصدر باختيار المستخدم وبعد المعاينة، وتتضمن نسخًا وإعدادات تقنية منقحة وأكواد أخطاء وأزمنة؛ استيرادها لا ينفذ أي محتوى.
- الروابط الموقعة وcookies لا تدخل نسخ إعدادات مشتركة أو سجلات تدقيق مؤسسات؛ التشفير المحلي وحده لا يحمي من برنامج يملك صلاحيات الحساب نفسه.

## بروتوكول اختبار الاعتمادية

كل حالة لها fixture ومراحل فشل ثابتة وبذرة عشوائية محفوظة وبصمة expected artifact، وتتكرر على الأنظمة والـfilesystems المعلنة. النجاح يقاس بصحة الملف والسجل وبقاء ملفات المستخدم، لا بمجرد عدم crash. قتل العملية لا يعادل فصل الطاقة؛ الثاني له اختبارات VM/جهاز مناسبة قبل ادعاء متانة ضده.

| المجموعة | حقن العطل/المدخل | معيار النجاح |
| --- | --- | --- |
| حفظ نطاق | انقطاع قبل write وبين short writes وقبل/بعد sync وقبل/بعد DB commit | لا نطاق موثوق دون بايتات سليمة؛ التقدم غير المسجل يعاد تنزيله بأمان |
| نشر ملف | انقطاع قبل intent وبعده وقبل/بعد rename وقبل Completed | ملف نهائي واحد صحيح أو حالة قابلة للاستعادة؛ لا فقد ولا استبدال ملف أجنبي |
| عطل تخزين | ENOSPC، I/O error، read-only، فصل قرص، تبديل وجهة | توقف مفهوم مع حفظ ما يمكن؛ لا Completed كاذب؛ استعادة بعد إصلاح السبب |
| استكمال HTTP | 200 بدل 206، Content-Range خطأ، جسم قصير/طويل، ETag متغير/ضعيف، 416، gzip | لا دمج تمثيلات مختلفة؛ transition صحيح ومسبب إلى إجراء أو تنزيل جديد |
| الشبكة | قطع اتصال، captive portal، TLS invalid، 429/503، بطء شديد، sleep/wake | لا قبول شهادة غير صالحة؛ محاولات محدودة؛ احترام Retry-After ضمن السياسة |
| جلسة متصفح | رابط منتهي، redirect cross-origin، POST/blob غير مدعوم، duplicate handoff | لا تسريب سر ولا إعادة POST تلقائية؛ عدم إلغاء المتصفح قبل durable receipt |
| التزامن | مئة أمر pause/resume/cancel متداخل، محرك ثان، آلاف مهام خاملة | انتقالات صحيحة، لا ازدواج كتابة، ضغط خلفي واستجابة UI ضمن هدف مقاس |
| ترقية | انقطاع تنزيل تحديث، توقيع غير صالح، فشل migration، اختلاف UI/engine | رفض آمن أو rollback مدعوم؛ احتفاظ بالحالة ونسخة احتياطية قابلة للقراءة |
| قاعدة البيانات | DB/WAL تالفة عمدًا، lock طويل، schema غير مدعوم | حفظ الأدلة/نسخة قبل الإصلاح، خطأ مفهوم؛ لا حذف صامت ولا فتح schema أحدث |
| نزاهة محلية | تعديل ملف part خارجيًا، رابط رمزي في الوجهة، collision عند rename | اكتشاف النطاقات التالفة؛ منع الكتابة خارج الوجهة أو استبدال المستخدم |

قاعدة WAL تحفظ محليًا وتنسخ بآلية متسقة؛ نسخ db وحدها أثناء التشغيل ليس إجراء backup معتمدًا لدينا. يتم اختبار restoration عمليًا. WAL checkpoint عملية مستقلة عن إثبات متانة ملف التنزيل. [SQLite WAL](https://www.sqlite.org/wal.html). مزامنة الملفات تعتمد على النظام والأجهزة وتحتاج تحققًا عمليًا. [Microsoft flushing I/O](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk).

## بوابات منع الإصدار

1. صفر عيب معروف يسمح بتلف صامت، خلط تمثيلين، الكتابة فوق ملف أجنبي، تجاوز مسار، تسريب جلسة، أو قبول تحديث غير موثوق.
2. مرور كل حالات الاستعادة الحتمية على كل منصة معلنة. حملة عشوائية موصى بها لا تقل عن 10,000 نقطة حقن لكل منصة؛ هذا هدف اختبار مقترح وليس نتائج منجزة أو برهانًا مطلقًا.
3. فحص تبعيات وSBOM وتراخيص، مراجعة حدود الثقة، وفحص أمني مستقل قبل الإطلاق العام. أي استثناء موثق بمالك وسبب وتاريخ معالجة، ولا يستثنى تلف البيانات أو ثغرة حرجة قابلة للاستغلال.
4. تثبيت نظام توقيع وإدارة مفاتيح وتدوير/إبطال واستجابة لتسرب مفتاح؛ rollback موثوق، لا تعطيل التحقق لمعالجة عطل توزيع.
5. اجتياز تثبيت/تحديث/إزالة ونقل إعدادات وإتاحة وRTL وعربية/إنجليزية على الأجهزة المعلنة، مع منع auto-run للملفات المنزلة.
6. runbook للحوادث والدعم؛ تعطل خدمة تجارية لا يمنع مستخدمًا من قراءة حالته المحلية أو حفظ مهامه.

## مؤشرات التشغيل والقياس

محليًا: زمن الحفظ وcommit، bytes المتلقاة مقابل المتينة، retries بحسب فئة السبب، زمن الاستعادة، فشل publication، نمو WAL وعمق الطوابير. تجاريًا: طلبات تفعيل ناجحة، زمن الخدمة وأخطاء الدفع دون محتوى المستخدم. أي SLO مدفوع أو SLA تعاقدي يحتاج ميزانية ومراقبة واختبارات حمل وفريق استجابة؛ لا يعلن الآن.

لوحة جودة الإطلاق تعرض العينة والنسخ والعتاد ومدة الاختبار والأعطال المفتوحة. تقارن throughput باختبار تسلسلي وبمنتجات مرخصة على نفس الشبكة والخادم، مع medians وpercentiles والتباين؛ لا تستخدم أسرع تشغيل منفرد كدعاية.

## قرارات لم تثبت بالتجربة بعد

تصميم حماية الإيرادات والترخيص ومقاومة تعديل العميل مفصل في [الترخيص ومقاومة العبث](licensing-and-tamper-resistance.md). التغييرات الحساسة تتطلب مراجعة Engineering وSecurity حسب [سياسة المراجعة](review-policy.md). الحماية من الكراك هدف دفاعي متعدد الطبقات مع حدود معلنة للعمل دون اتصال، وليست ضمانًا مطلقًا.

- سلوك نشر الملفات والمتانة على NTFS وAPFS وext4، وحدود دعم الشبكات والأقراص القابلة للإزالة.
- آليات التحقق من peer والعزل الفعلي لعامل الوسائط لكل منصة.
- صيغة التحديث والتوقيع وسياسة العمل دون اتصال والاستحقاق.
- إصدارات SQLite/Tauri والرخص والتحديثات الأمنية المحددة؛ تختار بعد مراجعة الإصدارات وتثبت في lockfiles، ولا تعتمد كلمة latest في حزمة إنتاج.

كل ادعاء أمني أو أداء يبقى هدفًا إلى أن يرتبط بتقرير اختبار قابل لإعادة الإنتاج.
