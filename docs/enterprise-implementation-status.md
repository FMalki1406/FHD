# تطبيق معمارية المحرك المؤسسي

اعتمد المستخدم تطبيق [الوثيقة المستهدفة](enterprise-engine-architecture.md). بدأ التنفيذ على نسختها الأولى؛ النسخة 4 (بعد ثلاث جولات مراجعة، 2026-09-22) هي المرجع الآن، وتُطابق الوحدات المنفذة معها تدريجيًا. هذا سجل التنفيذ الفعلي وتبعيات الانتقال. وجود واجهة trait لا يعني تنفيذ محولها، وأهداف الأداء لم تُقَس بعد.

## الوحدات المنفذة

| الوحدة | التنفيذ | الحد الحالي |
| --- | --- | --- |
| fhd-domain | أنواع صالحة بالبناء؛ JobSpec؛ آلة حالات Job مطابقة لـ§5.2 (النسخة 4): Stopping{then} مخرج وحيد مع ترتيب شدة الأسباب، Failed غير نهائية، كل إلغاء عبر Cancelling، أوامر no-op مقبولة؛ أحداث ذات إصدار؛ SegmentMap بالتقسيم والتأجير والجيل وإقرارات sync ثم commit؛ قرار retry حتمي | بلا I/O. الإقرار يرد من محول موثوق، ولا يثبت fsync بنفسه. نقل ملكية نطاق نشط غير منفذ. resume-policy جسر انتقالي نقي |
| fhd-app | AddDownload فوق Repository وAuthorizer وEntitlementGate، بمعاملة تجمع المهمة والإيصال ومصالحة تنافس القبول؛ منافذ SegmentStore وSegmentFile | بقية حالات الاستخدام وIPC والترخيص الإنتاجي لم تُنفذ |
| fhd-storage | ملف لكل جيل، كتابة موضعية خارج الترتيب، تغطية نطاقات، قفل وsync وبصمات وختم قبل النشر | نشر hard link فقط؛ لا fallback عبر الأقراص ولا حماية directory-handle ولا PublishIntent دائم |
| fhd-persistence | SQLite WAL/FULL وقبول ذري للمهمة والإيصال وحجز IDs وحذف بإصدار وtombstones؛ الترحيل 2: TransferRepository يحفظ إسقاط كل انتقال والنطاقات المتينة ذريًا ويعيد بناء المهام من المتين وحده؛ عمل محجوب محدود قبل الجدولة | مستودع قبول فقط؛ لا extents أو تحولات حالة التشغيل أو vault أو ترحيل بيانات المحرك القديم |
| fhd-http | منفذ Transport فعلي: قرارات البروتوكول كلها داخله، ولا يعبر الحد إلا نتيجة مصنفة | لا proxy ولا SSRF ولا سياسة شهادات؛ غير مربوط بثنائي ولا مختبر مع المنسق |
| fhd-runtime | BufferPool مشترك؛ Writer على خيط مخصص بحواجز sync/hash/verify؛ JobCoordinator لجلسة مهمة كاملة حتى النشر والتحرير؛ Scheduler يقبل بثلاثة سقوف وينام لأقرب موعد؛ OriginGovernor سلطة واحدة لكل أصل | مسار واحد لكل ملف؛ لا مشرف WriterPool؛ سقوف ثابتة بلا تكيّف ولا أولويات ولا preemption؛ لا مشرف يعيد تشغيل actor فاشل |
| fhd-testkit | مخزن ذاكرة ذري وحقن فشل قبل المعاملة وبعدها، وحاجز يفرض تنافس ثمانية طلبات | للاختبار فقط؛ ليس تخزينًا دائمًا |
| fhd-config | حدود متحقق منها ودمج default/user/enforced مع مصدر كل قيمة؛ تحليل إعداد proxy وحجبه | لا قارئات GPO/MDM أو PAC أو تطبيق حي على النقل |
| fhd-telemetry | أحداث برموز ثابتة وtracing فعلي وأغلفة أسرار محجوبة؛ حلقة ذاكرة محدودة ومقاييس ثابتة | لا دوران ملفات أو حزمة دعم أو رفع بيانات؛ الحجب لا يشمل tracing خارج هذه الواجهة |
| بوابة المعمارية | فحص اعتماديات normal/dev/build والمنصات والأسماء البديلة؛ منع اعتماد المحولات بعضها على بعض وIO داخل اعتماديات الدومين | لا يمنع استعمال std::fs في مصدر الدومين مباشرة؛ تستمر مراجعة الكود |

المحرك القديم ما زال المسار التنفيذي لـfhd-transfer. الوحدات الجديدة مختبرة بصورة مستقلة، ولم توصل بتحميل فعلي بعد. لذلك لم تُحل مشكلة الموجات بمجرد إضافة SegmentMap، ولم تُزل ازدواجية الحالة من المحرك القديم. لا توجد وحدات فارغة بأسماء بقية الطبقات توحي بأنها منفذة.

## عقود القبول

- SourceRef وDestinationRef يشيران إلى روابط غير قابلة للتعديل أو إعادة الاستعمال. تغيير الرابط أو الاعتماد أو السياسة أو الوجهة يصنع مرجعًا جديدًا. يجب أن يفرض محول التخزين هذا العقد عند تنفيذه.
- يحدد gateway هوية Principal بعد مصادقة نظام التشغيل؛ لا تأتي من جسم طلب المتصفح. المفتاح ثابت الحجم ومقيد بالهوية، وليس تفويضًا.
- الترتيب: تحقق الصلاحية، ثم إعادة إيصال سابق إن وجد، ثم فحص الاستحقاق لإنشاء جديد، ثم حجز الهوية والمعاملة الذرية، وأخيرًا الرد. انتهاء الاشتراك لا يمنع مصالحة طلب سبق قبوله.
- فشل commit قد يكون ملتبسًا؛ لا يُختلق نجاح ولا يُحذف عمل مقبول للتعويض. تعاد المحاولة بالمفتاح نفسه. إسقاط مستقبل انتظار الرد لا يلغي قبولًا اكتملت معاملته.
- يحتفظ مخزن الاختبار بإيصال المهمة المحذوفة. سياسة أرشفة الإيصالات للإنتاج تحتاج عقد إعادة إرسال صريحًا قبل تنفيذها.

| 3: النقل | منفذة جزئيًا: [محول HTTP](enterprise-http.md) بفحص واستئناف مربوط بمعرّف قوي وتصنيف أخطاء وتحويلات محكومة، مختبر بخادم داخل العملية؛ بقي proxy/PAC وفلتر SSRF وسياسة الشهادات والربط بثنائي |
| 4: التشغيل | منفذة جزئيًا: BufferPool ومسار Writer وJobCoordinator ومحول HTTP موصول ونشر فعلي، و[المجدول وحاكم الأصول](enterprise-runtime.md) بسقوف ثابتة؛ بقي المشرف وإعادة توزيع الاتصالات والأولويات والقياسات |
| 5: IPC والعملاء | منفذة جزئيًا: [جذر تركيب وثنائي fhd-engine](enterprise-daemon.md) ينزّل وينشر فعليًا، وعدة طلبات في تشغيلة واحدة عبر المجدول؛ بقي Named Pipe وUDS وnative host وخدمة مقيمة |

| 7: التصلب | مفتوحة: deny/audit وSBOM وfuzz وقياسات التراجع؛ لا دليل لأهداف 1Gbps أو CPU أو 10000 مهمة |

## المراجعة والتحقق

فُصل التنفيذ عن مراجعتي Engineering وSecurity. رُبطت تذاكر حفظ النطاقات بالنطاقات والمحاولات الفعلية بعد اكتشاف خطر تبادل إقرار بين خريطتين لهما المعرفات نفسها. أزيل Clone العام من سلطة الخريطة، وتراجع انتقالات التوقف أثناء checkpoint ضمن اختبارات الدومين.

تغطي اختبارات التطبيق فقد رد المعاملة، وفشل الحفظ، والتعارض، وثمانية طلبات متنافسة، وانتهاء الاستحقاق، والسعة وإيصالات الإزالة. تسجل نتائج التشغيل النهائية في [حالة التنفيذ](execution-status.md).

[قرارات السلامة](enterprise-safety-decisions.md) تصحح تفاصيل الوثيقة: لا SetFileValidData، ولا سرقة نطاق نشط بمجرد تغيير نهايته، ولا استكمال مجهول لمجرد ETag، ولا مشاركة عميل بين سياسات proxy/TLS متناقضة. هذه العقود لا تعني أن المحولات نُفذت.

تفاصيل الدفعة التالية وحدودها: [الملفات](enterprise-storage.md)، [SQLite](enterprise-persistence.md)، [الذاكرة والكاتب](enterprise-runtime.md). لا تتحول نطاقات الدومين إلى Durable بسبب اختبار محول مستقل؛ ما زال يجب ربط sync بمعاملة extents حقيقية ومنع إعادة الكتابة فوق النطاقات المعتمدة داخل المنسق قبل تفعيل المحرك الجديد.

نجحت الدفعة على الأنظمة الثلاثة في [CI](https://github.com/FMalki1406/FHD/actions/runs/35644474152) عند الكود `51de1bb60282626924799e0a51b659f2bdaf9edd`. عولج اختبار زمني قديم بفصل دليل الإلغاء الحتمي عن زمن تجهيز الشبكة والقرص؛ التفاصيل والنتائج المحلية في سجل التنفيذ. تبقى حالات المراحل أعلاه جزئية رغم نجاح CI.
