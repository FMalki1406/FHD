# مراجعة الكود — 2026-09-21

المراجع الوظيفي: Engineering Agent. النطاق: `tools/http-lab/server.mjs` و`server.test.mjs` و`cli.mjs` و`package.json` ووثائق المختبر. مراجعة قراءة وتشغيل الاختبارات، بلا تعديل كود. لا يوجد محرك Rust أو واجهة React أو ترخيص أو تحديثات أو CI في الملفات المفحوصة؛ لم تتم مراجعة هذه الأنظمة ولم يثبت أمانها.

## نتيجة التحقق

شغلت `npm.cmd test` على Windows في `D:\Projects\FHD` باستخدام Node `v22.13.1`: **14 ناجحًا، صفر فشل، صفر تخطٍ**. النتيجة تثبت سلوك fixtures واختبار إعادة تركيب في الذاكرة، لا سلامة محرك أو قرص أو حصانة من الكراك. رقم Node هنا وصف لبيئة التشغيل، وليس اعتمادًا لأحدث إصدار آمن أو لسياسة دعمه.

## الملاحظات المفتوحة

هذه ملاحظات تحسين وتغطية، وليست ثغرات منتج مثبتة. لم أرصد ضمن النطاق المحدود عيبًا يستوجب تصنيف P0/P1. أرقام الأسطر تخص النسخة التي قرئت في هذا التاريخ.

### ENG-001 — P2 — بيئة التشغيل غير مثبتة لإعادة الإنتاج

الموقع: [package.json، السطر 6](../package.json#L6). الحقل `engines.node` يسمح بكل نسخة `>=22`، ولا يوجد ملف تثبيت runtime أو تعريف CI ضمن ملفات المشروع المفحوصة. النتيجة: قد يعمل أعضاء الفريق ببيئات مختلفة، ولا تكفي نتيجة النجاح الحالية لإعلان دعم كل النسخ المسموح بها.

المطلوب: تثبيت نسخة اختبار مرجعية محددة ومدعومة بعد فحص المصدر الرسمي، وتعريف مصفوفة منفصلة إذا أردنا دعم أكثر من نسخة. حفظ النسخة في تقرير النتائج وتعريف CI. لا يلزم إدخال تبعيات خارجية أو lockfile صوري لهذا المختبر ذي التبعيات المدمجة فقط. الحالة: مفتوح، المالك Engineering.

### ENG-002 — P2 — ادعاء اتساق الاستجابة أثناء تغير النسخة يحتاج اختبارًا متزامنًا

الموقع: [server.mjs، السطر 74](../tools/http-lab/server.mjs#L74)، و[server.test.mjs، السطر 75](../tools/http-lab/server.test.mjs#L75). الكود يلتقط body وvalidator لكل طلب، وهي آلية معقولة؛ لكن الاختبار الحالي يغير النسخة بعد اكتمال الطلب الأول، فلا يحمي invariant الطلب الجاري من regression.

المطلوب: بدء `/slow`، انتظار وصول أول بايت، تغيير النسخة ثم بدء طلب ثان؛ يجب أن يطابق الأول بالكامل المرجع القديم وETag القديم، والثاني المرجع الجديد. لا تستخدم نومًا ثابتًا لتخمين بداية النقل. هذه فجوة تغطية وليست إثبات خلط حالي. الحالة: مفتوح، المالك Engineering/QA.

### ENG-003 — P2 — الإغلاق أثناء نقل نشط غير مختبر

الموقع: [server.mjs، السطر 155](../tools/http-lab/server.mjs#L155)، و[server.test.mjs، السطر 21](../tools/http-lab/server.test.mjs#L21). الاختبارات تغلق المختبر بعد انتهاء طلباتها. مسار إتلاف sockets وإلغاء timers وقت وجود `/slow` نشط لم يتحقق منه اختبار مباشر.

المطلوب: تشغيل نقل بطيء، انتظر أول بيانات، استدعِ `close()`، وتحقق ضمن مهلة كلية أن الإغلاق يحسم وأن الطلب ينتهي/يفشل كما يحدد العقد ولا تبقى عملية المختبر معلقة. أضف الحالة التي فيها أكثر من طلب نشط. الحالة: مفتوح، المالك Engineering/QA.

### ENG-004 — P3 — صياغة تعليق حدود المتصفح أوسع من الشرط

الموقع: [server.mjs، السطر 37](../tools/http-lab/server.mjs#L37). التعليق يقول إنه يرفض وصول المتصفح عبر أصل مختلف؛ الشرط الفعلي يرفض الطلبات ذات Origin أو Host غير متوقع، ويقبل العميل المحلي الذي لا يرسل Origin. لا ينبغي استخدام هذا الشرط مستقبلًا كتفويض IPC أو كإثبات منع كل طلب ينشأ من المتصفح.

المطلوب: تضييق التعليق لما يضمنه الكود، والمحافظة على أن المحتوى اصطناعي فقط ولا توجد عملية تغيير حالة عبر HTTP. أي إضافة لاحقة لبيانات مستخدم أو أمر مؤثر تحتاج نموذج تفويض جديدًا ومراجعة Security. لم يثبت هنا تسريب بيانات، لأن المختبر لا يقدم بيانات مستخدم. الحالة: مفتوح، المالك Engineering/Security.

## نقاط سليمة شوهدت فعليًا

- الاستماع على loopback فقط عند السطر 145، مع حدود اتصال ومهل عند 135–138؛ لا وصول إلى ملفات أو URLs يحددها المستخدم.
- تغيير النسخة متاح عبر واجهة برمجية محلية فقط عند 149، وليس endpoint HTTP.
- اختبار إعادة التركيب يرفض تبديل وتكرار أجزاء المرجع عند أسطر الاختبار 48–53؛ هذا أقوى من fixture متكرر البايتات قد يخفي الخلط.
- حالات 200 بدل 206، If-Range قديم وضعيف، Content-Range خاطئ، جسم ناقص ونطاقات غير صالحة ممثلة في الاختبارات.
- دليل المختبر يعلن صراحة حدود الدليل وعدم تمثيل كامل دلالات HTTP؛ هذا متسق مع التنفيذ المفحوص.

## قرار المراجعة

مناسب كأساس مختبر محلي محدود مع الملاحظات أعلاه. لا يمنح الموافقة على إطلاق منتج أو حماية ترخيص. قبل الاعتماد عليه في CI متعدد البيئات، عالج ENG-001 وأضف ENG-002 وENG-003؛ التصحيح التوثيقي ENG-004 ضمن أول تحسين للمختبر. قواعد الكود التالي في [معايير الهندسة](engineering-standards.md)، ويجب أن ترافق كل معالجة نتيجة تحقق جديدة دون إعادة توصيف النتائج السابقة.
