# ذاكرة النقل ومسار الكتابة الجديد

هذه لبنات تشغيل فعلية في `fhd-runtime` وليست بعد بديلًا مشغّلًا لمحرك CLI القديم. تعتمد على منافذ التطبيق، ولا تستورد محول القرص أو SQLite مباشرة.

## BufferPool

ميزانية مشتركة بين النسخ، بكتل يعاد استخدامها حجمها حتى 256 KiB. يؤخذ تصريح الكتلة قبل تخصيصها، ويظل معها حتى يعيدها الكاتب إلى قائمة الاستخدام. عدد الكتل هو قسمة الميزانية على حجم الكتلة مع التقريب للأسفل؛ السقف 512 MiB. تحتسب الكتلة كاملة ولو حملت بايتًا واحدًا، وتصفّر الشريحة المرئية قبل تسليمها لمهمة أخرى.

الحد يخص بيانات هذه الكتل؛ لا يشمل ذاكرة HTTP/TLS أو النواة أو وصف الطوابير أو RSS الكامل. الكتل الحرة تبقى في التجمع لإعادة الاستخدام. الانتظار يقبل الإلغاء، وإغلاق التجمع يمنع قبول طلبات جديدة.

## Writer

يمتلك خيط نظام واحد مقبض الملف لكل مسار كتابة، ويتلقى أوامر عبر قناة محدودة بين 1 و256 أمرًا. لا ينشأ `spawn_blocking` لكل شريحة. يجمع الكاتب الكتابات المتجاورة المنتظرة في الكتلة الأولى دون تخصيص حمولة جديدة؛ يحده حجم الكتلة وسعة دفعة الأوامر. لا ينتظر وصول بيانات إضافية عمدًا، ولا يتجاوز فجوة أو حاجز sync/hash. لذلك ليس ضمانًا لتحويل بث بايت/ثانية إلى كتابة كبيرة؛ يجب أن يجمع قارئ HTTP اللاحق قراءاته أيضًا.

يأتي رد الكتابة بعد انتهاء I/O وإرجاع رصيد الكتل. sync حاجز FIFO، لكنه لا يثبت التزام المعاملة. الخطأ في القرص يسمم المسار وتفشل الأوامر التالية دون I/O إضافي. الإلغاء قبل قبول الأمر يمنع وصوله للقرص؛ إسقاط منتظر رد أمر مقبول لا يلغي I/O ولا يحرر الجيل قبل انتهائه.

`shutdown` يغلق القبول وينتظر التصريف وانتهاء الخيط. إسقاط Writer يغلق القناة فقط ويترك المقبول يتصرف على خيطه؛ يجب على المنسق انتظار shutdown صراحة قبل انتقال الجيل. يوجد استدعاء blocking واحد عند الانضمام للخيط، وليس داخل حلقة كتابة البيانات.

## ما لم يُنفذ

- مشرف WriterPool مشترك يحد عدد الخيوط عبر المهام.
- JobCoordinator وScheduler وربط HTTP وخريطة النطاقات بمعاملات SQLite.
- التحقق من lease/attempt وحماية النطاقات التي التزم بها أثناء الجلسة؛ Writer يتحقق من هوية الملف والجيل والحدود فقط.
- مسار `write → sync → commit extents` واستعادة النطاقات ومصالحة PublishIntent من البداية إلى النهاية.
- قياسات الإنتاجية وCPU وأهداف الوثيقة؛ اختبارات السلوك ليست benchmark.

## المراجعة والاختبارات

راجع Engineering وSecurity الملكية والحدود والإلغاء. الاختبارات الحتمية تغطي إعادة استخدام الكتل وحجب بيانات المهمة السابقة، رفض الجيل والحدود، تصريف المقبول بعد إسقاط المنتظر، عمل الكتابة والمزامنة على خيط واحد، تسميم المسار بعد خطأ write أو sync، انهيار العامل وإرجاع الذاكرة، ودمج ثلاث كتابات متجاورة دون تجاوز حاجز sync مع فحص البايتات الفعلية. نتائج التشغيل في [حالة التنفيذ](execution-status.md).
