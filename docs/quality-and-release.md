# خطة الجودة وتأهيل الإطلاق

التاريخ: 2026-09-21. الحالة: خطة تحقق مقترحة، بلا نتائج قياس للتطبيق. لم تُنفذ حملة اختبارات التطبيق الواردة هنا. مختبر HTTP المحلي منفذ ومختبر كأساس هندسي مستقل، وليس محرك تنزيل أو دليل جاهزية المنتج. نتائج المختبر في [سجل التنفيذ](execution-status.md).

## معنى الجودة المؤسسية

الجودة المطلوبة تعني سلامة الملفات، أمان حدود الثقة، دعمًا محددًا وقابلًا للاختبار، تحديثًا قابلًا للتعافي وتشغيلًا يمكن دعمه. وصف المنتج بـ enterprise لا يثبت امتثالًا أو اعتمادًا أو توافرًا مضمونًا. إدارة الأجهزة المركزية وSSO وSLA وتوزيع المؤسسات التزامات منتج وتجارية منفصلة، ولا تُعد مدعومة بمجرد جودة تطبيق سطح المكتب.

ترتبط هذه الخطة بـ[نطاق الإطلاق](launch-plan.md)، و[التوجه التقني](technical-direction.md)، و[قائمة التنفيذ](delivery-backlog.md). مراحل التحقق داخلية؛ لا تخفض نطاق الإطلاق إلى MVP.

## قواعد لا تقبل الاستثناء

- لا تظهر حالة مكتمل قبل تحقق سياسة السلامة ونشر الملف النهائي بنجاح.
- لا يدمج التطبيق نسختين مختلفتين من المورد، ولا يعتبر تساوي الاسم والحجم دليل تطابق.
- لا تُكتب أسرار الجلسة في السجلات أو صادرات التشخيص ولا تُرسل إلى وجهة تحويل مختلفة تلقائيًا.
- لا يستبدل التطبيق ملفًا موجودًا دون سياسة صريحة يراها المستخدم.
- فشل الترخيص أو الواجهة أو التحديث لا يبرر حذف بايتات المستخدم المحفوظة.
- قياس داخلي ناجح لا يسمح بإعلان دعم نظام أو حالة متصفح لم تُختبر.

المختبر المنفذ يستخدم Node وأدواته المدمجة؛ أوامر التشغيل `npm test` و`npm run lab:serve`. لا تعني اختبارات خادم المختبر أن سيناريوهات محرك التنزيل نجحت. تغطي fixtures أجزاء من Q-01 وQ-02 وQ-03 وQ-11 وQ-13؛ الحدود موثقة في [دليل المختبر](../tools/http-lab/README.md)، وتظل القدرات الأخرى مخططة.

## مصفوفة الأعطال والقبول

| المعرّف | الحالة | القبول |
| --- | --- | --- |
| Q-01 | Range صحيح، بلا Range، و200 بدل 206 | مسار محافظ، بلا دمج جسم كامل داخل نطاق جزئي؛ الناتج يطابق المرجع |
| Q-02 | Content-Range خاطئ، 416، حجم مجهول أو طول متناقض، انتهاء جسم مبكر | لا نجاح زائف؛ خطأ قابل للفهم أو إعادة طلب آمنة ومحدودة |
| Q-03 | تغير ETag أو الملف أثناء الاستكمال؛ ضعف/غياب أدوات التحقق | لا خلط للنسخ؛ حفظ السابق وتوضيح الحاجة إلى بدء جديد عند تعذر الإثبات |
| Q-04 | ضغط المحتوى مع النطاقات وتبدل Content-Encoding | اتساق تمثيل البايتات؛ رفض الاستكمال غير المتوافق |
| Q-05 | قتل المحرك قبل/بعد الكتابة وتثبيت البيانات ومعاملة checkpoint | إعادة البناء من النطاقات المؤكدة؛ إعادة تنزيل الجزء غير الموثوق فقط وفق السياسة |
| Q-06 | قطع الطاقة المحاكى أو إعادة تشغيل النظام، لا مجرد قتل العملية | اختبار متانة فعلي على جهاز/آلة مناسبة؛ لا اعتماد على ذاكرة نظام الملفات وحدها |
| Q-07 | انقطاع قبل/بعد التحقق وإعادة تسمية الملف وتسجيل الاكتمال | استعادة متسقة بلا حذف أو ملف مكتمل وهمي أو تكرار غير مفسر |
| Q-08 | امتلاء القرص، رفض الإذن، فصل قرص، تغيير مسار | توقف قابل للاستعادة، حفظ الأجزاء، إجراء واضح دون الكتابة إلى قرص بديل خفيًا |
| Q-09 | ملف جزئي عُدل خارجيًا أو تلفت قاعدة البيانات | لا ثقة عمياء في التقدم؛ تحقق/عزل واستعادة آمنة مع تفسير |
| Q-10 | انقطاع شبكة وDNS وTLS؛ نوم/استيقاظ وتبدل Wi-Fi | محاولات محدودة بلا دوران سريع؛ استعادة عند عودة المورد المؤهل |
| Q-11 | 403، 404، 429 وRetry-After، 500/502/503 | تمييز سبب الفشل؛ احترام الانتظار وحدود إعادة المحاولة وإمكانية الإلغاء |
| Q-12 | رابط مؤقت جديد يشير لنسخة مختلفة | إعادة تحقق من الهوية؛ لا استكمال تلقائي اعتمادًا على الاسم |
| Q-13 | تحويل دائري أو عبر أصل مختلف؛ URL/اسم/رأس خبيث | حدود للتحويلات والتحقق من المدخلات وعدم تسريب الاعتماد |
| Q-14 | فشل التطبيق عند تسليم المتصفح؛ رسالة مكررة أو نسخة بروتوكول مختلفة | لا إلغاء مبكر لتنزيل المتصفح؛ هوية مهمة تمنع تكرار المعالجة؛ مسار واضح للفشل |
| Q-15 | POST وblob وجلسة لا يمكن نقلها | إبقاء الحالة غير المدعومة في المتصفح؛ لا إعادة إرسال مؤثرة تلقائيًا |
| Q-16 | تزوير IPC وتجاوز الحجم والمسار والروابط الرمزية | رفض الرسالة أو المسار خارج الصلاحية؛ لا أوامر تنفيذ مشتقة من المدخلات |
| Q-17 | تحديث معدل/منقطع؛ ترحيل قاعدة البيانات يفشل | رفض غير الموثوق؛ استعادة نسخة تشغيل صالحة وبيانات متوافقة؛ لا رجوع أعمى إلى مخطط قديم |
| Q-18 | خادم ترخيص غير متاح؛ تكرار إشعار دفع؛ ساعة جهاز تغيرت | تطبيق سياسة موثقة، معالجة متكررة آمنة، استمرار المهمة الجارية وحماية البيانات |
| Q-19 | تغير منطقة زمنية وتوقيت صيفي وفوات موعد أثناء النوم | تنفيذ سياسة واضحة للفوات والتكرار؛ لا تشغيل مهمة مرتين دون قصد |
| Q-20 | HLS/DASH ناقص أو متغير؛ تعطل أداة الدمج | تحقق من الاكتمال قبل النجاح، عزل الأداة، وتفسير حدود الاستكمال والصيغ |

## مصفوفة المنصات المقترحة

هذه أهداف تغطية وليست قائمة دعم منشورة. تُثبت أرقام إصدارات النظام والمتصفح وصورة الجهاز عند بدء التأهيل، بعد التحقق من دعم المورد والتقنية المختارة. لا يُستنتج نجاح منصة من نجاح منصة أخرى.

| البيئة المستهدفة | الاقترانات المقترحة | شرط التأهيل |
| --- | --- | --- |
| Windows x64 | Chrome وEdge وFirefox؛ Brave بتحقق منفصل | تثبيت مستخدم عادي، WebView، تسجيل Native Messaging، تحديث وتكامل النظام على جهاز فعلي |
| macOS Apple Silicon | Chrome وEdge وFirefox؛ Brave بتحقق منفصل | جهاز فعلي، توقيع وتوثيق توزيع، Keychain، أذونات وتحديث |
| Linux x64: توزيعة LTS من عائلة Debian | Chrome وFirefox؛ متصفحات إضافية حسب اعتماد التوزيع | Wayland وX11 حيث معلن، حزمة فعلية، تسجيل الإضافة واختلافات سطح المكتب |
| Linux x64: توزيعة من عائلة Fedora | Chrome وFirefox حسب التوافر | اختبار الحزمة المستهدفة والاعتماديات والصلاحيات والتحديث |
| Windows ARM وmacOS Intel وLinux ARM | غير محسوم | قرار تكلفة/طلب ثم تأهيل مستقل قبل إعلان الدعم |
| Safari | لاحقًا كما في المصدر | خارج قائمة الإطلاق الحالية |

تغطية المتصفح الأولية: الإصدار المستقر الفعلي وقت الاختبار والسابق إذا ظل مناسبًا لسياسة الدعم؛ Firefox ESR عند اعتماده. لا تُعرض هذه القاعدة كضمان دائم دون دورة صيانة. تشمل الاختبارات العربية والإنجليزية، الفاتح والداكن، تكبير 100% و200%، قارئ الشاشة المتاح بكل نظام، لوحة المفاتيح ومسارات Unicode. الأقراص الأساسية: NTFS وAPFS وext4؛ الخارجية والشبكية لها قبول منفصل وحدود منشورة.

## بيئة القياس والأهداف الأولية

كل القيم أدناه **provisional / مقترحة**؛ ليست نتائج أو وعود تسويق. تُثبت بعد أول قياس ممثل وقبل تأهيل الإصدار، ويُوثق سبب أي تعديل بدل تحريك الحد لإخفاء فشل.

البيئة المرجعية المقترحة: جهاز فعلي لكل نظام، 4 أنوية فعلية أو أكثر، ذاكرة 16 GiB، SSD محلي، شبكة سلكية 1 Gbit/s وخادم مستقل لا يمثل عنق الزجاجة. يُسجل طراز CPU والقرص ونظام الملفات وإصدارات OS/WebView والمتصفح وحالة الطاقة. البناء إنتاجي بلا أدوات تطوير؛ جميع عمليات التطبيق التابعة تدخل قياس CPU والذاكرة. CPU هنا نسبة من قدرة الجهاز الكلية. تكرر اختبارات الزمن 30 مرة، النقل 10 مرات، والخمول 10 دقائق بعد دقيقتي استقرار؛ تنشر الوسيط وp95 والقيم الخام.

| المؤشر | الهدف الأولي المقترح | حمل القياس |
| --- | --- | --- |
| سلامة الناتج | صفر اختلاف بصمة وصفر نجاح زائف في الحملة المحددة | ملفات مرجعية 1 MiB و100 MiB و10 GiB و100 GiB مع Q-01 إلى Q-13 |
| زمن تشغيل الواجهة | p95 ≤ 3 ثوانٍ | بدء بارد و10,000 سجل؛ يفصل زمن استعادة المهام |
| البحث المحلي | p95 ≤ 200 ms حتى عرض النتائج | 50,000 سجل ومرشحات وأسماء عربية/إنجليزية |
| استجابة التحكم | p95 ≤ 200 ms لإقرار أمر محلي | 20 مهمة نشطة؛ الإقرار لا يساوي اكتمال طلب الشبكة |
| CPU الخمول | متوسط ≤ 1% | لا تنزيلات ولا تحقق أو تحديث نشط |
| ذاكرة الخمول | مجموع الذاكرة الخاصة ≤ 250 MiB | نافذة مفتوحة و10,000 سجل؛ توضح طريقة الحساب بكل نظام |
| ذاكرة الحمل | ≤ 500 MiB ونمو مستقر | 20 مهمة و64 اتصالًا كحد اختبار، بما فيها الواجهة والعمليات التابعة |
| كفاءة النقل | وسيط ≥ 90% من خط أساس أحادي الاتصال متماثل | ملف 10 GiB؛ HTTP والإعدادات والخادم والشبكة متطابقة؛ تُقاس التجزئة منفصلة |
| فقد العمل بعد قتل العملية | بايتات يعاد تنزيلها ≤ ما استُقبل في آخر 5 ثوانٍ + 16 MiB لكل مهمة | مورد ثابت يدعم الاستكمال؛ ميزانية متانة أولية لا تشمل تلف قرص أو ملف غير موثوق |
| استعادة قائمة المهام | p95 ≤ 5 ثوانٍ | 100 مهمة غير مكتملة؛ ظهور الحالة قبل انتظار ردود الشبكة، لا يعد الملف مستأنفًا بعد |
| اختبار الاستمرارية | 72 ساعة، بلا عطل غير معالج أو نمو مستمر للموارد | خليط ملفات وأخطاء و20 مهمة؛ التحقق من كل ناتج مكتمل؛ فحص داخلي أولي عند 24 ساعة |
| قابلية الاستخدام | ≥ 90% إكمال أول تنزيل دون مساعدة عند التأهيل | 10 مشاركين جدد على الأقل؛ اختبار UX-001 الأولي يستهدف 80% خلال 5 دقائق قبل تحسين التجربة للتأهيل؛ نتيجة اتجاهية بعينة صغيرة |

حملة الأعطال الهندسية الأولية: 1,000 حقن قتل عملية ببذور مسجلة موزعة على نقاط الحفظ والنشر لكل منصة. حملة تأهيل الإصدار المستهدفة: 10,000 نقطة حقن لكل منصة، وفق وثيقة الأمن والاعتمادية، و50 دورة انقطاع/استعادة شبكة، و20 دورة نوم/استيقاظ لكل منصة معتمدة. هذه أعداد تغطية مقترحة وليست إثباتًا رياضيًا أو ضمانًا لمعدل فشل ميداني. لا يجوز استبدال اختبار قطع الطاقة بقتل عملية وتسميتهما متكافئين.

الأدوار توزيع مسؤولية مطلوب وليست ادعاء وجود فريق موظف. لا عيب P0/P1 مفتوح عند الإطلاق: فقد/تلف بيانات، تسريب سر، تحديث غير موثوق، تعطيل مسار أساسي بلا بديل أو فشل دفع جوهري. P2 يحتاج تقييم أثر ومالك وموعد علاج؛ لا يسمح الاستثناء بتجاوز قواعد السلامة. النشر الفعلي والتكاليف والصلاحيات الخارجية لها قرارها المنفصل.

## سجل الأدلة المطلوب لكل مرشح

يحفظ تقرير Markdown رقم الإصدار وبصمة الحزمة ومعرف المصدر والتاريخ والمنفذ وبيئة الاختبار والسيناريو وبذرة العشوائية والنتيجة والقياسات والعيوب المتبقية. تحفظ المخرجات الكبيرة في ملفات مرتبطة؛ لا تُدرج أسرار أو روابط مستخدمين. حالات النتائج: لم يُختبر، نجح، فشل، محجوب مع السبب. لا يُستبدل «لم يُختبر» بـ«مدعوم».

بعد الإطلاق، يُعاد التأهيل عند تغيير المحرك أو التخزين أو جسور المتصفحات، وتُراجع مصفوفة الدعم مع تحديثات الأنظمة. قياسات الميدان اختيارية ومنقحة وفق سياسة الخصوصية؛ لا نجمع سجل تنزيل المستخدم لإثبات الجودة.
