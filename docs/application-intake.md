# استقبال اقتراحات الواجهة والمتصفح

الحالة: `intake::Inbox` حد داخلي داخل العملية بين اقتراح غير موثوق وموافقة المتحكم المحلي. ليس إضافة متصفح ولا خادم IPC جاهزًا. الاقتراح يحمل رابط HTTPS ومعرف طلب محدودًا فقط؛ لا يحدد مسارًا أو cookies أو رؤوس اعتماد أو سماح HTTP أو تحويلات. اقتراح الرابط لا يجري DNS أو شبكة أو كتابة قرص ولا يلغي تنزيل المتصفح.

القائمة محدودة بـ64 اقتراحًا، تنتهي بعد 15 دقيقة؛ نفس معرف الطلب والرابط يرجع الاقتراح ذاته، وتغيير الرابط بالمعرف نفسه يرفض. بعد موافقة محلية صريحة على الرابط والوجهة والاسم، ينشئ المتحكم المهمة عبر `Manager::enqueue_once` وينتظر إقرار الحفظ. يرفض هذا المسار المدير الذي يعمل في الذاكرة فقط؛ حفظ الإقرار الدائم متاح على Windows ضمن مخزن الطابور الحالي.

## هوية المصدر وإعادة الإرسال

المتحكم الموثوق ينشئ Inbox::for_source باسم ثابت يمثل الإضافة وملف المستخدم المعتمدين. الاسم ليس حقلًا تختاره صفحة ويب ولا وسيلة مصادقة بحد ذاته. Default مخصص للمتحكم المحلي باسم local-ui. يدمج Inbox اسم المصدر ومعرف الطلب ببصمة SHA-256 محددة الإصدار وبأطوال حقول صريحة، فلا يتصادم معرف طلب واحد بين مصدرين مختلفين.

يجب أن يبقى معرف الطلب فريدًا داخل المصدر عبر إعادة التشغيل؛ لا تستخدم عدادًا يبدأ من الصفر كل تشغيل. بعد فقد الرد أو إعادة التشغيل يعيد المصدر الطلب بمعرفه الأصلي والخيارات الأصلية التي وافق عليها المستخدم. يعود معرف المهمة المحفوظ نفسه، ولا ينشأ تنزيل آخر. يرفض تغيير الرابط أو الوجهة أو الاسم أو الخيارات بالمفتاح نفسه. إذا حذف المستخدم المهمة من القائمة، يعود PreviouslyRemoved ولا يعاد إنشاؤها.

يبقى الاقتراح غير الموافق عليه في الذاكرة فقط ويحتاج إعادة الإرسال بعد التعطل. لا يمنع سجل مؤقت إعادة الطلب المقبول؛ المرجع هو الإقرار المشفر المحفوظ مع المهمة. نجاح إعادة الطلب لا يعيد حالة المهمة إلى بدايتها ولا يلغي تعديلات المستخدم اللاحقة عليها. لا تعدل إعدادات القبول الافتراضية في إصدار مستقبلي دون ترحيل واضح أو احتفاظ المرسل بالإعدادات الأصلية وإصدار البروتوكول.

المعاينة قد تتضمن رابطًا موقعًا حساسًا فلا تسجل أو تصدر تلقائيًا. هوية الطلب ليست تفويضًا للاستعلام العام عن المهام أو إيقافها، وعودة الإقرار لا تجيز إلغاء تنزيل المتصفح آليًا. قبول محلي مرة واحدة لا يعني exactly-once بين التطبيق والمتصفح؛ يلزم بروتوكول تسليم فعلي واختبارات انقطاع على الطرفين.

## المتبقي قبل الربط الخارجي

إضافة Chrome/Edge/Firefox وصلاحياتها، تسجيل native messaging وربط هوية المصدر، سياسات DNS/IP ومنع الوصول غير المصرح إلى الشبكات الخاصة، عزل أسرار الجلسات بحسب نطاقها ومسارها وعمرها، واختبار التسليم بعد التعطل. لا منفذ محلي يستمع في هذه الدفعة؛ typed API لا يجعل بيانات الصفحة موثوقة.
