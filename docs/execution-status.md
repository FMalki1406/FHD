## نتيجة التحقق الفعلية

أحدث تحقق Rust بعد المراجعة والإصلاحات: Windows x64 وRust 1.98.1؛ `cargo test --workspace --locked --offline` نجح **19/19** (10 core و9 resume)، و`cargo fmt --all -- --check` نجح، وClippy لكل targets مع `-D warnings` نجح دون تحذيرات. هذه اختبارات قواعد خالصة، لا نقل ملفات أو قاعدة بيانات أو تطبيق سطح مكتب.

المراجعة المتبادلة بين وكيلي Engineering وSecurity، ومراجعة المنسق، أدت إلى ربط AttemptToken بهوية DownloadId لمنع قبول حدث مهمة أخرى، وتنقيح Debug للرؤوس الخام ومنع طباعة قيمها. اختبارات الإغلاق والهوية والتنقيح نجحت بعد الإصلاح. لا ثغرة ذات أثر إنتاجي مثبت لأن ناقل الشبكة وIPC لم ينفذا؛ الضوابط تمنع أخطاء تكامل مستقبلية.

قرار محافظ موثق: سياسة الاستكمال الحالية تتطلب Content-Length صريحًا؛ بعض استجابات 206 الصحيحة مثل chunked بلا هذا الرأس تُرفض الآن. قبولها لاحقًا يحتاج تغيير عقد ومراجعة. Completed يعتمد على أحداث من منسق موثوق، وليس إثباتًا أن هذه الوحدة نفذت مزامنة ملف أو نشره.

### مختبر HTTP

- البيئة: Windows x64، Node.js v22.13.1، npm 10.9.2.
- الأمر النهائي: `npm.cmd test` من جذر المشروع.
- النتيجة الأحدث: 16 اختبارًا، 16 ناجحًا، صفر فشل/تخطي/إلغاء؛ خروج العملية 0. النتيجة السابقة قبل إضافة اختبارات المراجعة الهندسية كانت 14/14.
- تشمل التغطية: تطابق البصمة وHEAD، إعادة تركيب نطاقات متوازية، النطاقات المفتوحة واللاحقة، 416، تغير ETag مع نفس الحجم، رفض weak If-Range للاستكمال، تجاهل Range، انقطاع الجسم، Content-Range خاطئ، نقل بطيء، التحويلات والأخطاء، رفض طرق وأصول غير مدعومة، وعدم انهيار المختبر لعنوان طلب مشوه.
- النتيجة دليل صحة fixtures الأساسية فقط؛ لا تثبت تنزيلًا متينًا إلى القرص، أو استعادة SQLite، أو جاهزية تطبيق أو أي منصة أخرى.
- التنفيذ الأول باستخدام `node --test` تعثر بسبب `spawn EPERM` في بيئة التشغيل المقيدة. شُغلت نفس اختبارات `node:test` مباشرة في العملية، وجرى ضبط أمر npm عليها. لم تُحذف اختبارات لتجاوز الفشل ولم تُرفع صلاحيات.

## المراجعة المستقلة والإصلاحات

وكيل المعمارية راجع كود المختبر بعد تنفيذه:

1. بيانات fixture القديمة تتكرر كل 256 بايت وقد تخفي تبديل الأجزاء. استبدلت بكتل SHA-256 حتمية مرتبطة بالإصدار وموضع الكتلة، وأضيف تحقق أن تبديل أو تكرار جزء يغير الملف.
2. request-target مشوه قد يرمي استثناء URL ويسقط الخادم. أضيف رفض network-path references ومعالجة التحليل وفحص الأصل؛ اختبار يثبت بقاء الخادم عاملًا بعد الطلب المشوه.

أُعيدت الاختبارات بعد الإصلاحين ونجحت النتيجة الموثقة أعلاه.

المراجعة الهندسية الإضافية أضافت اختبار بقاء جسم وETag استجابة جارية متسقين عند تغير المورد، واختبار إغلاق ثلاث استجابات نشطة دون تعليق، وصححت تعليق حدود الحماية من طلبات المتصفح. نجحت الاختبارات الستة عشر بعدها. تثبيت runtime وCI ما زال ENG-001 مفتوحًا؛ نسخة Node المذكورة بيئة اختبار فعلية وليست اعتمادًا أمنيًا أو قائمة دعم إنتاجي.

## قرارات تكامل الوثائق

- البحث: هدف مقترح p95 ≤ 200ms عند 50,000 سجل حتى عرض النتائج.
- الاستمرارية: 24 ساعة محطة هندسية داخلية، و72 ساعة هدف تأهيل الإصدار.
- حقن الأعطال: 1,000 نقطة في الحملة الهندسية الأولية، و10,000 لكل منصة هدف تأهيل؛ ليست نتائج منجزة.
- قابلية الاستخدام: هدف مبكر 8/10 خلال 5 دقائق في UX-001، وهدف تأهيل ≥90% دون مساعدة. العينات الصغيرة اتجاهية فقط.
- الأهداف أعلاه مقترحة إلى أن تُثبت بيئة القياس وتُعتمد قبل التأهيل، ولا تستخدم كوعود تسويق الآن.

## البيئة والعمل التالي

كان Rust غير موجود، ثم جرى إعداد Rust الرسمي داخل `.tools` بالمشروع بعد التحقق من بصمة المثبت. ثُبت الإصدار 1.98.1 مع rustfmt وclippy؛ لم يُعدل PATH العام ولم يثبت SDK إضافي. لا شراء أو نشر أو تواصل خارجي. أوامر التشغيل والتفاصيل في [بيئة التطوير](development.md).

الخطوات التالية بحسب التبعيات:

1. بناء منسق يربط هوية المورد والجيل وengine epoch مع حالات المهمة وسياسة الاستكمال.
2. استكمال عقد الحالات للجدولة والفشل الدائم والأوامر المكررة والتعافي من تخزين فعلي؛ الأساس الحالي في الذاكرة فقط.
3. إنشاء محول HTTP آمن وربطه بالمختبر، ثم تخزين النطاقات والنشر والتعافي من قتل العملية وفشل القرص.
4. تجربة Tauri ودورة حياة المحرك وإتاحة الوصول على الأنظمة المستهدفة؛ بيئة Windows الحالية لا تثبت macOS أو Linux.
5. تصميم المسارات الرئيسية واستكمال البحث التجاري؛ القرارات المالية والاسم والتوزيع الخارجي تحتاج بيانات تجارية وموارد قبل التنفيذ.

## غير المنجز

قرار مضاف: الدفع في موقع مستقل، والتطبيق للتفعيل وحالة الرخصة. وُثقت رحلة الشراء وربط الاستحقاق ومعايير القبول في [الموقع التجاري](web-commerce.md)، مع تحديث المتطلبات والمعمارية والترخيص وقائمة التنفيذ. هذا توثيق قرار فقط؛ لم يُنشأ الموقع أو تكامل دفع.

واجهة التطبيق، ناقل HTTP ومنسق محرك كامل، قاعدة الحالة، إضافات المتصفح، الوسائط، الترخيص والدفع، التوقيع والتحديث، اختبارات الأجهزة، بحث العملاء الميداني، والتأهيل التجاري. Rust الحالي قواعد خالصة فقط. لا نسبة إنجاز إجمالية ولا موعد إطلاق معتمد.
