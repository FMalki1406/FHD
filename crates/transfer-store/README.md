# تخزين التنزيل التسلسلي

الحالة: تنفيذ أولي للاستخدام الهندسي، وليس إعلان جاهزية تجارية. الملف المصدر يمنع unsafe محليًا؛ SQLite نفسه يستخدم شيفرة أصلية عبر التبعية المدققة.

## العقد

- `Store::create` ينشئ مجلد مهمة جديدًا فقط؛ لا يتبنى مجلدًا موجودًا. الاسم النهائي مكوّن بسيط مع منع المسارات والأسماء المحجوزة على Windows.
- `Identity` يحتفظ بالمصدر الأصلي والنهائي وETag والحجم والبصمة المتوقعة الاختيارية. لا تنسيق Debug لهوية المورد أو التخزين؛ الأخطاء تنقح تفاصيل SQLite ومسارات IO. هذه الوحدة لا تتحقق من سياسة URL؛ يفرضها منسق الشبكة قبل الإنشاء.
- ملف `owner.lock` عليه قفل نظام حصري غير منتظر طوال ملكية Store. تحرير العملية يحرر القفل؛ ملف القفل المتبقي ليس علامة تعطل بحد ذاته.
- `append` تسلسلي محدود بالحجم؛ فشل الكتابة قد يترك ذيلًا غير مسجل ويمنع إعادة استعمال الكائن قبل إغلاقه والاستعادة.
- `checkpoint`: مزامنة ملف part أولًا، ثم معاملة SQLite ضمنية ذرية تسجل الحجم وبصمة SHA-256 للتقدم. الفشل لا يتحول إلى نجاح.
- فشل الكتابة أو checkpoint أو حفظ علامة اكتمال النقل أو finalize يمنع استعمال الكائن لمزيد من التعديلات حتى إغلاقه وإعادة فتحه. قد تنجح كتابة الإيصال على القرص ثم يفشل تأكيدها؛ إعادة الفتح تقرأ الحقيقة المحفوظة وتتحقق من البايتات بدل الاعتماد على الحالة القديمة في الذاكرة. حتى خطأ التصادم أو التحقق داخل finalize يستلزم إعادة الفتح قبل محاولة أخرى؛ هذه سياسة محافظة.
- `open` يتحقق من طول وبصمة الجزء المسجل قبل أي تعديل. في حالة Downloading فقط يزيل الذيل غير المسجل من ملف المهمة. بعد اكتمال النقل، أي اختلاف طول يفشل مع إبقاء البايتات، بما فيها تعديلات المستخدم على الملف المنشور.
- `mark_transfer_complete` إقرار من منسق النقل بأنه تحقق من انتهاء الجسم دون خطأ؛ وصول عداد البايتات إلى الحجم وحده لا يكفي. العلامة محفوظة منفصلة وتسبق الإكمال.
- `finalize` يتحقق من الحجم والبصمة المتوقعة إن توفرت، ثم يسجل PublishIntent وينشر hard link على نفس المجلد دون overwrite. يبقى part موجودًا كوصلة لنفس الملف؛ لا حذف تلقائي.
- `open` لا ينفذ نشرًا أو إكمالًا تلقائيًا؛ يرجع ReadyToPublish للنية غير المكتملة كي يتحقق المنسق من ربط المهمة وخياراتها والإلغاء قبل `finalize`. الاستعادة بعد PublishIntent تتحقق من الملف النهائي مقابل الحجم والبصمة قبل اعتماد Published؛ وجود ملف بلا intent لا يمنح حق تبنيه حتى لو كانت بايتاته متطابقة.

## حدود الضمانات الحالية

هذه API متزامنة وحجبها مقصود لعامل تخزين مستقل عن واجهة التطبيق وasync runtime؛ فحص SHA-256 يقرأ بذاكرة ثابتة 64 KiB وقد يستغرق وقتًا لملف كبير. الاستعادة والتحقق النهائي الكاملان لا يملكان إلغاء داخل القراءة بعد؛ يلزم تفويضهما لعامل مملوك ومراقب.

مجلد المهمة يجب أن يكون تحت مجلد خاص بالتطبيق محمي بصلاحيات المستخدم. تُرفض symlinks وWindows reparse points المعروفة في الأسلاف والمدخلات الموجودة، وتُشترط ملفات عادية. الفحص لا يوفر حماية من عملية خبيثة بنفس المستخدم تستبدل الملفات بين الفحص والفتح؛ لا يوجد claim sandbox أو حماية ضد local admin. تهيئة ACL خاصة بمجلد التطبيق لم تنفذ هنا، ولا توفر قاعدة SQLite تشفيرًا للروابط الموقعة. منسق النسخة الهندسية يجب أن يقيد المصادر العامة غير المحتوية على credentials/secrets؛ دعم الروابط الحساسة مؤجل لمخزن أسرار النظام.

اختيار SQLite `journal_mode=DELETE` مع `synchronous=FULL` بدل WAL مؤقت ومقصود لوحدة ذات كاتب واحد؛ يبسط آثار sidecars ويمنع الحاجة إلى قارئ متزامن. checkpoint هنا حفظ تقدم وليس عملية SQLite WAL. فشل الإنشاء يترك مجلدًا ناقصًا للفحص ولا يحذفه تلقائيًا.

مزامنة دليل النشر تنفذ على Unix فقط. على Windows تعتمد استعادة تعطل العملية على إعادة التحقق من الملفات وreceipt؛ **لم تُثبت متانة انقطاع الطاقة أو بيانات الدليل على Windows**. القرص يجب أن يدعم hard links؛ الملفات الشبكية وFAT والنشر بين أقراص مختلفة غير مدعومة في هذه المرحلة. retained part يعني تعديل المستخدم للملف المنشور يظهر أيضًا في part، والاستعادة ترفض اختلافه دون تغييره.

## التبعيات

- `rusqlite = 0.40.2`، bundled SQLite: محول SQLite، رخصة MIT، مستودع [rusqlite](https://github.com/rusqlite/rusqlite)، [توثيق الإصدار](https://docs.rs/rusqlite/0.40.2/rusqlite/). bundled يبني SQLite الأصلي عبر build script وC compiler؛ لا إضافات load_extension ولا تحميل مكتبات امتداد مفعل في API.
- `sha2 = 0.11.0`: تنفيذ SHA-256 من RustCrypto، MIT أو Apache-2.0، [المصدر](https://github.com/RustCrypto/hashes)، [توثيق الإصدار](https://docs.rs/sha2/0.11.0/sha2/). البصمة تكشف اختلاف البايتات ولا تثبت هوية ناشر الملف دون قيمة متوقعة موثوقة.
- النسخ الدقيقة للمكونات الانتقالية في Cargo.lock الجذري. هذه مراجعة غرض وحدود أولية، وليست ادعاء تدقيق supply chain كامل أو خلو من ثغرات. أوصى وكيل Security بهذين الإصدارين بعد التحقق من المصادر الرسمية.

## التحقق

الاختبارات تستخدم ملفات وSQLite ومجلدات مؤقتة حقيقية، وتشمل: استعادة الذيل، رفض تلف أو نقص الأجزاء دون حذف، قفل مالك واحد، collision بلا overwrite، فجوتي النشر قبل/بعد hard link، وجوب انتهاء transport، استمرار شرط checksum بعد إعادة الفتح، منع المسارات وتجاوز الحجم، حفظ تعديل المستخدم للملف النهائي، ومنع نشر ذيل غير متوقع.

نتائج التشغيل الفعلية تضاف في سجل التنفيذ الجذري بعد تشغيل مجموعة workspace؛ تعريف الاختبارات لا يعني نجاحها. مراجعة Security المستقلة اكتشفت خطر تقصير الملف المنشور إذا عدّل المستخدم نهايته وخطر نشر ذيل زائد، وأُصلحا مع اختبارات منع الانتكاس.

### حقن أعطال التخزين

أضيفت تسعة اختبارات على ملفات وقاعدة SQLite حقيقية: كتابة جزء من القطعة ثم إرجاع StorageFull، فشل المزامنة قبل إيصال التقدم، إجهاض SQLite لتحديث الإيصال أو مراحل اكتمال النقل/نية النشر/اكتمال النشر عبر trigger حقيقي وRAISE(ABORT)، فشل إنشاء hard link، وفشل المزامنة بعد إنشائه. تشمل الحالات أيضًا خطأً بعد حفظ إيصال التقدم أو النشر وقبل تأكيد نجاح العملية، وتصادم ملف مستخدم بعد فشل النشر.

الاختبارات تثبت منع التقدم الكاذب، رفض إعادة استعمال كائن أخفق، استعادة آخر إيصال محفوظ فعليًا، عدم اختراع نهاية نقل سليمة، وإبقاء ملفات المستخدم دون استبدال. نقاط الحقن خاصة بكل كائن وموجودة فقط تحت cfg(test)؛ لا متغيرات بيئة أو إعدادات أو API تشغيلية لتعطيل الكتابة أو المزامنة، ولا تبعيات جديدة.

هذه **محاكاة محدودة لمسارات الخطأ**؛ لم نملأ القرص أو نفصل الطاقة، وإجهاض trigger لا يحاكي كل أعطال SQLite أو وحدة التخزين. نجاحها لا يغلق بوابة متانة انقطاع الطاقة، أو النشر على Windows، أو اختبارات الأنظمة الأخرى.

## مخطط v2 وتقليل بيانات الرابط

Identity يحفظ original_url_fingerprint وfinal_url_fingerprint من 32 بايت بدل نص الرابط. url_fingerprint يحسب SHA-256 مع تمييز الغرض؛ التطبيع مسؤولية المتصل. المخطط v1 يُرفض قبل إعداد قاعدة البيانات للكتابة ودون تعديل ملفها أو الجزء. لا ترحيل تلقائي أو تنظيف للنسخ القديمة. ETag والاسم والمحتوى ليست مشفرة؛ لا ادعاء خلو المهمة من الأسرار. تفاصيل وقيود [مراجعة الخصوصية](../../docs/privacy-review.md).
