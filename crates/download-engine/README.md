# ناقل الملفات الداخلي

تنفيذ Rust للنقل المتوازي يربط HTTP بسياسة الاستكمال والتخزين المتين. أداة تطوير محلية وليست واجهة المنتج أو إصدارًا للعملاء.

## التشغيل

من جذر المشروع في PowerShell، بعد تحضير التبعيات:

```powershell
./tools/rust.ps1 -CargoArguments @('build', '--bin', 'fhd-transfer', '--locked', '--offline')
'https://example.com/file.zip' | ./target/debug/fhd-transfer.exe ./local-job file.zip
npm.cmd run test:engine
```

مجلد المهمة يجب ألا يكون موجودًا عند البداية؛ إعادة نفس الأمر تستعيد المهمة الموجودة. المجلد الأب موثوق ومملوك للمستخدم. يقرأ الرابط من stdin لتجنب وضعه في معاملات العملية. لا تستخدم روابط سرية أو موقعة في هذه التجربة: مخطط SQLite v2 يحفظ بصمتي الرابط بدل نصه، لكن ETag وبيانات أخرى تبقى غير مشفرة؛ حماية التخزين بوابة إصدار مفتوحة.

الخيارات: `--allow-http` للسماح الصريح بـHTTP في المختبر، `--sha256` لبصمة متوقعة من 64 خانة hex، `--checkpoint-bytes` (افتراضيًا 1MiB، حتى 64MiB)، `--max-bytes` (افتراضيًا 100GiB). يجب إبقاء الرابط والاسم والبصمة نفسها عند الاستعادة. Ctrl+C يطلب إلغاءً مع checkpoint؛ نجاح حفظه شرط إعادة خطأ الإلغاء. رمز الخروج 0 نجاح، 2 فشل، 130 إلغاء.

## ما ينفذه

- TLS بالتحقق الافتراضي للشهادات؛ لا تجاوز للتحقق. تعطيل proxy التلقائي والضغط وReferer. مهلة اتصال 15 ثانية ومهلة قراءة 30 ثانية.
- حتى خمسة تحويلات، داخل الأصل افتراضيًا ومع قائمة سماح صريحة لعبور الأصل في المكتبة. رفض credentials داخل الرابط وfragment والمخططات غير HTTP(S).
- تنزيل ذو طول معروف أو استجابة مجهولة الطول ذات تأطير سليم، ورفض رؤوس متناقضة ومحتوى multipart/مضغوط. حد حجم قبل إنشاء المهمة.
- الاستكمال يتطلب strong ETag و206 ونطاقًا وطولًا متطابقين. استجابة 200 أثناء الاستكمال لا تضاف للملف الجزئي.
- كتابة محدودة القطع عبر عامل قرص، وcheckpoints بعد مزامنة البيانات. مقارنة SHA-256 المتوقعة إن زودها المتصل قبل نشر الملف.
- لا نجاح قبل اكتمال جسم الاستجابة والتحقق والنشر دون استبدال. بلوغ الحجم وحده لا يكفي.

## القيود الحالية

النقل المتوازي متاح عبر --connections من 1 إلى 8. الطابور الدائم المشفر على Windows وإعادة المحاولة وحدود السرعة العامة متاحة عبر Manager؛ CLI لا يشغّل هذا المدير. انظر docs/durable-queue-and-retries.md وdocs/parallel-downloads.md. تدعم المكتبة Authorization وCookie صريحين وتحويلات مسموحة إلى أصول محددة، مع حذف الاعتماد عند عبور الأصل. يدعم الناقل استجابة chunked مجهولة الحجم؛ لا يستكمل جزئيًا هذا النوع بعد انقطاعه. لا واجهة أو قناة IPC أو إضافة متصفح فعلية بعد. المهمة التي حفظت كامل الحجم دون علامة نهاية نقل سليمة ترفض الاستكمال وتحتاج مسار إعادة بدء صريح لاحقًا. SHA-256 المحلي يكتشف التغيير لكنه لا يثبت أصالة المصدر دون بصمة موثوقة مستقلة.

Store هو صاحب سجل الاستعادة؛ نموذج حالات download-core محلي لكل استدعاء، ولا يمثل بعد سجل أحداث متعدد المهام. بعد بدء عملية التحقق والنشر النهائية لا تقاطعها إشارة الإلغاء. حد الحجم لا يغني عن حصة القرص أو اختبار امتلائه. لا سياسة DNS/IP لمداخل المتصفح بعد؛ هذه أداة لمستخدم محلي موثوق فقط.

تُترك وصلة `.part` بعد النشر لدعم التحقق والاستعادة؛ التنظيف والترحيل لاحقان. لا ادعاء متانة فصل الطاقة على Windows أو دعم مجرّب للأنظمة الأخرى. تفاصيل [التخزين](../transfer-store/README.md)، [مراجعة الأمان](../../docs/network-storage-security-review.md)، [نتائج الاختبارات](../../docs/execution-status.md).

## توافق التخزين

المهام الجديدة تستخدم schema v2 وبصمات روابط SHA-256 مع تمييز الغرض. إعادة الاستكمال تتطلب نفس الرابط بما فيه query؛ تحديث الرابط الموقّع لا يمر تلقائيًا. تُرفض مهام v1 القديمة بخطأ UnsupportedStorageVersion دون تحويل أو حذف، وتبقى روابطها القديمة كما كانت. البصمة ليست تشفيرًا وتسمح بمقارنة تخمينات. [مراجعة الخصوصية](../../docs/privacy-review.md).

أخطاء التخزين الآن تميز تعارض الوجهة، تلف البيانات، اختلاف البصمة، قفل المهمة، وإصدار التخزين غير المدعوم. خطأ I/O يعرض ErrorKind فقط دون رسالة النظام الخام أو مسار الملف أو الرابط. هذا تصنيف داخلي لدعم قرارات واجهة لاحقة؛ ليس ترجمة رسائل مستخدم نهائية أو ترخيصًا لإعادة المحاولة العمياء.

## إدارة عدة تنزيلات

أضيفت وحدة manager داخل download-engine لإدارة طابور FIFO وتحديد عدد التنزيلات النشطة والإيقاف المؤقت والاستئناف والإغلاق الذي ينتظر الكتابة. عقدها وحدودها في [مدير المهام](../../docs/task-manager.md). واجهة CLI الحالية ما زالت تنزّل ملفًا واحدًا؛ مدير المهام API مكتبة يُختبر عبر الشبكة، ولم يربط بواجهة رسومية بعد.

## حد سرعة اختياري

Options.bytes_per_second وCLI --bytes-per-second يحددان وتيرة استهلاك جسم الملف لكل محاولة. راجع [سياسة السرعة](../../docs/bandwidth-policy.md) للحدود والفرق عن سرعة الشبكة الفعلية. استُبدلت read_timeout بمهلة صريحة لكل انتظار HTTP كي لا ينتهي التنزيل بسبب انتظار تحديد السرعة نفسه.
