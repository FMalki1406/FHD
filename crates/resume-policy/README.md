# سياسة الاستكمال الآمن

الحالة: منطق Rust منفذ بلا شبكة أو ملفات أو تبعيات خارجية. التنفيذ ليس محرك تنزيل ولا يثبت متانة البيانات. نتائج التشغيل والمراجعة تسجل في [حالة المشروع](../../docs/execution-status.md).

## العقد

`ResumeRequest` يثبت النطاق نصف المفتوح والحجم وETag قوي لتمثيل identity. `ResponseHeaders` يحافظ على حالة الرأس المفقود أو المتكرر؛ على محول HTTP استعمال `Repeated` عند وجود أكثر من حقل وعدم إسقاط القيم الزائدة أو اختيار أول قيمة. حد القيمة 8192 بايت، ويطبق قبل إزالة SP وHTAB المحيطة.

`evaluate` يقبل قراءة جسم 206 فقط عندما تتطابق البداية والنهاية والحجم وETag وطول المحتوى ويغيب Content-Encoding أو يكون identity وحده. طلبنا محدد البداية والنهاية؛ استجابة أقصر ترفض أيضًا. غياب Content-Length أو تعدده يرفض حتى إن سمح بروتوكول HTTP باستجابة أخرى قابلة للمعالجة. هذه سياسة منتج محافظة.

استجابة chunked صحيحة دون Content-Length ترفض للاستكمال بهذه السياسة أيضًا؛ قبولها لاحقًا يحتاج عقد قياس جسم ومراجعة صريحة.

200 ينتج `RestartSeparately`: لا يسمح بإلحاق جسمه بالأجزاء القديمة ولا يأمر بحذفها أو بدء تنزيل تلقائي. 416 ينتج `Revalidate` دائمًا ولا يثبت اكتمالًا. بقية الحالات مرفوضة لهذه السياسة؛ سياسة التحويلات وإعادة المحاولة منفصلة.

`ReadRange` يسمح بقراءة جسم محدود فقط. يجب على محول النقل تعطيل فك الضغط الآلي، حصر الاستجابة في نطاق مفرد، التحقق من framing في HTTP ومن نهاية الجسم النظيفة، رفض تجاوز البايتات المتوقعة أثناء القراءة، ثم استدعاء `verify_received_length`. لا يسجل المحرك أي نطاق متين قبل اكتمال هذه الشروط والكتابة والمزامنة. تطابق العدد دون نهاية نقل سليمة غير كافٍ.

يجب أن يربط منسق التنزيل الطلب بالجيل الحالي وURL النهائي وسياق الطلب وأصل المورد قبل تطبيق القرار. هذه الوحدة لا تملك تلك المعلومات ولا تثبت أصالة خادم يكذب بشأن ETag. لا تستخدم ETag وحده لدمج موارد من URLs مختلفة. لا تفحص الوحدة multipart أو Transfer-Encoding؛ يرفض محول HTTP framing الملتبس واستجابات multipart قبل تمريرها، ولا يقدم حقولًا بعد فك ضغط تلقائي.

## التحليل والأمان

المرجع هو [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html): أقسام 8.6 و8.8.3 و14.4. القيم تحلل كبايتات لدعم obs-text في ETag دون تحويل UTF-8 فاقد. لا إزالة escaping، ولا ثقة بـweak validators أو Last-Modified. تقبل وحدة التحليل الحجم المجهول نحويًا لكن سياسة الاستكمال ترفضه. تستخدم الحسابات checked u64، ولا تخصص الوحدة ذاكرة بحسب رؤوس الخادم. لا أخطاء تحتوي على URL أو قيمة رأس؛ طباعة StrongEtag وField وResponseHeaders منقحة.

## التحقق

اختبارات الوحدة تغطي تغير الهوية والحدود والحجم، طول جسم ناقص أو زائد، 200 و416، الرؤوس المتكررة والمفقودة، الضغط المتعدد، حقن CR/LF، الأعداد المتجاوزة وu64 القصوى وETag byte grammar. التشغيل من جذر workspace: `cargo test -p resume-policy --locked --offline`.

تحقق فعلي 2026-09-21: Windows x64، Rust 1.98.1 المحلي، التنسيق نجح و9/9 اختبارات نجحت، دون تخطي أو فشل. أمر PowerShell: `./tools/rust.ps1 -CargoArguments @('test', '-p', 'resume-policy', '--locked', '--offline')`. أصلحت ملاحظة Engineering المستقلة عن طباعة قيم الرؤوس الخام، وأضيف اختبار عدم تسريب القيم في التشخيص.

غير منفذ هنا: اختبارات HTTP فعلية مع المختبر، fuzzing مستمر، توليد طلب If-Range، TLS والتحويلات وحفظ الأجزاء. لا تعني اختبارات الدوال اجتياز هذه البوابات.
