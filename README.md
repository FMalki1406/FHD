# وثائق المشروع

المستودع: [FMalki1406/FHD](https://github.com/FMalki1406/FHD).

حالة المشروع: نُفذ ناقل HTTP بأجزاء متوازية، واستكمال محافظ وتحقق SHA-256 ونشر بلا استبدال، ومدير مهام بإعادة محاولة وحدود سرعة مشتركة وحفظ مشفر للطابور على Windows. التنفيذ أداة هندسية داخلية؛ تطبيق سطح المكتب والترخيص والموقع لم تُبن بعد. [حالة التنفيذ والأدلة](docs/execution-status.md).

## التوجه المعتمد

- الهدف إطلاق منتج متكامل وجاهز للمنافسة، وليس MVP.
- قوة الإطلاق تُقاس بالقيمة المقدمة وتجربة الاستخدام والجودة والجاهزية التشغيلية، وليس بعدد الميزات وحده.
- تُوثق متطلبات المنتج وقراراته وخططه وتقدم العمل في ملفات Markdown داخل المشروع.
- يتولى المساعد دور Product Owner: صياغة المنتج والمتطلبات، ترتيب الأولويات، تحديد معايير القبول، ومتابعة التنفيذ والتحقق من الجودة ضمن الأدوات والصلاحيات المتاحة.
- تُرفع للمستخدم القرارات الجوهرية والالتزامات المالية والإجراءات التي تحتاج صلاحياته. لا تُعد هذه المسؤولية تفويضًا مفتوحًا للدفع أو النشر أو التواصل الخارجي.

## أسلوب العمل والتوثيق

- تُفصل الحقائق المعتمدة عن الافتراضات والأسئلة المفتوحة.
- تُوثق القرارات عند اتخاذها وتُحدّث الوثائق عند تغيرها.
- يُفصل العمل المخطط له عن المنفذ والمتحقق منه.
- يُحدد نطاق إطلاق متكامل بعد فهم الفكرة والسوق؛ تقسيم التنفيذ إلى مراحل داخلية لا يعني إطلاق MVP.
- يتحدد موعد الإطلاق بناءً على معايير جاهزية موثقة، ولا يُفترض موعد أو ميزانية قبل مناقشتهما.

## الوثائق التي ستُبنى مع تقدم العمل

ستغطي الوثائق رؤية المنتج، السوق والمنافسين، الجمهور، عرض القيمة، نموذج العمل، متطلبات المنتج، رحلات المستخدم، التصميم، المتطلبات التقنية، الأمان والخصوصية، خطة التنفيذ، الاختبارات، التشغيل، التسويق، وخطة الإطلاق ومؤشرات النجاح، بحسب طبيعة الفكرة.

## نقطة البداية

الخطوة التالية: توسيع اختبارات TLS والإلغاء وأعطال القرص وحماية بيانات الروابط، ثم ربط المحرك بتجربة سطح المكتب وإدارة المهام. لا يُعد نجاح المختبر إطلاقًا للمنتج.

## تشغيل التحقق الحالي

يتطلب Node.js 22 أو أحدث، ولا يتطلب تنزيل مكتبات خارجية:

```sh
npm test
npm run lab:serve
```

الاختبارات تخص مختبر الخوادم التجريبي فقط. خادم المختبر محلي ويعرض عنوانه عند التشغيل؛ أوقفه بـCtrl+C.
